## 1. 공고를 업무로 분해하기

### 1.1 조직 문장이 이미 질문 축을 알려준다

지원자 대부분이 "업무" 항목만 읽고 조직 소개문을 흘려보낸다. 그런데 조직 문장에 **검증 대상의 계층**이 그대로 적혀 있다.

> Analog-Digital **Mixed IP**, **Digital IP** 및 **Subsystem/Top Level** 검증 업무를 맡고 있는 조직 (…) 설계 무결성 확보를 목표로 (…) **검증 시스템 및 환경 구축, 검증 모델 개발**

여기서 세 가지를 읽어야 한다.

1. **검증 대상이 3계층이다** — Mixed IP / Digital IP / Subsystem·Top. 면접 질문은 이 계층을 오르내리며 나온다. "IP 레벨에서 닫은 것을 Top에서 또 검증하나요?" 같은 질문이 대표적이다.
2. **"설계 무결성 확보"가 목표다** — sign-off 판단을 묻겠다는 뜻이다. "언제 검증이 끝났다고 말할 수 있나요?"
3. **"검증 시스템·환경 구축, 검증 모델 개발"** — 테스트를 *돌리는* 사람이 아니라 *만드는* 사람을 뽑는다. 여기가 이 공고의 성격을 결정한다.

:::note[면접에서 말할 포인트]
3번을 읽었다는 것을 초반에 드러내라. "테스트 케이스를 작성하는 일보다 **환경과 모델을 만드는 일**의 비중이 크다고 이해했습니다"라고 말하면, 공고를 읽은 사람과 훑은 사람이 구분된다.
:::

### 1.2 업무 4문장 → 실제로 하는 일

| 공고 문장 | 풀어 쓴 업무 | 예상 질문 |
|---|---|---|
| In-house, 3rd Party Digital IP 및 **Mixed 설계** 검증 | 자체 설계 IP·구매 IP·아날로그 혼재 블록을 모두 맡는다 | "3rd Party IP는 어디까지 검증하나요?" |
| **In-house VIP 개발** + 3rd Party VIP 도입·활용 | 표준 프로토콜은 사서 쓰고, 비표준은 직접 만든다 | "언제 만들고 언제 사나요?" |
| **UVM 기반 검증 환경 구성** 및 Test Case 개발 | env/agent/scoreboard 계층 설계 + 시나리오 | "환경을 재사용 가능하게 만드는 원칙은?" |
| **Regression** 통한 Code/Func. Coverage Closure | 정기 회귀 + coverage 수렴 관리 | "closure를 어떻게 판단하나요?" |

네 문장이 **VIP → 환경 → 테스트 → 회귀·coverage** 라는 하나의 흐름이다. 면접에서도 이 순서로 파고들 가능성이 높다.

### 1.3 요구 역량이 만드는 좌표축

필수 4항목을 다시 보면 무게중심이 분명하다.

1. SystemVerilog/UVM **VIP·Testbench·Test Case 개발**
2. Digital IP **Spec 기반 검증 계획 수립 및 검증 프로세스 이해**
3. 신규 Protocol 또는 Custom IP에 대한 **UVM Agent 설계/구현**
4. **Code/Functional Coverage Closure**

그리고 우대 3항목:

1. **Spec 기반 Custom UVM Agent A-to-Z 개발 경험**
2. HBM, **DDR/LPDDR** Memory 검증
3. **Full-Chip Mixed-Level Design (Schematic & RTL) 검증**

여기서 결정적인 관찰 하나. **필수③과 우대①이 같은 것을 가리킨다.** 필수에서 "Custom IP UVM Agent 설계/구현"을 요구하고, 우대에서 다시 "Spec 기반 Custom UVM Agent **A-to-Z**"를 요구한다. 같은 역량을 두 번 적는 공고는 흔하지 않다 — **이 조직이 지금 가장 아쉬운 자리**라는 신호다.

:::caution[전략 판단]
공고에서 두 번 반복된 항목이 면접의 무게중심이다. 준비 시간을 균등 배분하지 말고 [03 — Custom UVM Agent A-to-Z](../03_custom_uvm_agent/)에 가장 많이 써라. 나머지는 "막히지 않는" 수준이면 충분하다.
:::

## 2. 강점과 갭을 정직하게 매핑하기

11개 항목에 자신의 경력을 대조한다.

| 공고 항목 | 내 경력 매칭 | 판정 |
|---|---|---|
| 필수③ Custom IP **UVM Agent 설계/구현** | MMU IP **Custom Thin VIP** 자체 개발 | **강력 매칭** |
| 우대① Spec 기반 Custom Agent **A-to-Z** | 동일 (스펙만 보고 밑바닥부터) | **강력 매칭 — 최대 무기** |
| 필수① SV/UVM VIP·TB·Test Case | Secure Boot UVM Framework 전면 리팩토링 | 강력 매칭 |
| 필수② Spec 기반 검증계획·프로세스 | Secure Boot 다수 양산 sign-off | 매칭 |
| 필수④ Coverage Closure | MMU from-scratch coverage 100% | 매칭 |
| 업무② In-house VIP vs 3rd Party | **상용 VIP를 버리고 자체 개발한 판단 경험** | 강력 매칭 |
| 업무③ UVM 환경 구성 | 모듈화·이식성 중심 환경 재설계 | 매칭 |
| 업무④ Regression·Coverage | 프로젝트 전반 | 매칭 |
| 우대② HBM, **DDR/LPDDR** 검증 | DRAM Memory Controller IP (LPDDR4/5, Follow) | **부분 매칭** (controller 레벨) |
| 업무① **Mixed 설계** 검증 | 없음 | **갭** |
| 우대③ **Full-Chip Mixed-Level (Schematic & RTL)** | 없음 | **갭** |

핵심 진단은 두 줄로 요약된다.

- **갭은 사실상 하나다** — Mixed(Schematic & RTL). 업무①과 우대③이 같은 갭을 가리킨다.
- **공고가 두 번 강조한 항목이 내 최대 강점과 겹친다** — Custom UVM Agent A-to-Z.

:::tip[DRAM 공고와의 전략 차이]
같은 회사의 [DRAM 설계검증 공고](../../dram_dv_interview/01_role_and_strategy/)에서는 갭이 셋(custom 회로 검증·Mixed·STA)이었고, 그래서 전략이 **비대칭**이었다 — 부족한 도메인 축은 깊이로 상쇄하고 AI 축을 차별화로 전면 배치.

HBM 검증 공고는 다르다. 갭이 하나뿐이고 공고의 무게중심이 내 강점과 정면으로 겹친다. 따라서 **정면승부**가 맞다 — Custom Agent를 클라이맥스로 놓고, AI는 차별화가 아니라 *환경 구축 역량의 증거*로 격을 낮춰 배치한다.

전략을 그대로 복사하면 안 되는 이유가 여기 있다. 공고가 다르면 서사도 달라진다.
:::

## 3. 관통 메시지 — 한 문장

재포지셔닝은 한 문장에서 출발한다. 공고가 반복 강조한 것을 문장의 주어로 삼는다.

> "스펙만 있는 비표준 인터페이스를 받아 **UVM Agent를 밑바닥부터 세워 본** 사람. 상용 VIP를 쓸지 만들지 판단해 봤고, 그 환경으로 양산 sign-off까지 냈다. HBM Base Die의 Custom IP 검증에 즉시 투입될 수 있다."

이 문장의 설계 의도:

- **주어가 공고의 무게중심**(Custom Agent A-to-Z)이다.
- "판단해 봤다"가 **업무②**(In-house vs 3rd Party)를 정확히 맞춘다.
- "양산 sign-off"가 **필수②**(검증 프로세스)와 조직 문장의 "설계 무결성 확보"에 닿는다.
- 갭(Mixed)은 문장에 넣지 않는다. 성장 계획에서 따로 처리한다.

:::caution[하지 말아야 할 문장]
"메모리 검증 경험이 있습니다"를 첫 문장으로 쓰지 마라. DRAM Controller는 Follow였고, 면접관은 HBM 검증 경험자와 비교한다. **내가 이길 수 있는 축**(Agent 설계·환경 구축)을 주어로 삼아야 한다.
:::

## 4. 10분 PT의 구성과 순서

역량 3축으로 묶고 프로젝트를 그 증거로 배치한다. 순서는 *적합성 → 깊이 → 클라이맥스 → 기여·성장*.

| # | 슬라이드 | 내용 | 대응 공고 항목 |
|---|---|---|---|
| 1 | 표지 | 관통 메시지 한 줄 + 검증 이력 요약 | — |
| 2 | 경력 흐름 + 3축 | 타임라인 + 오늘 말할 3축 (Agent·환경·프로세스) | 전체 |
| 3 | **① Custom UVM Agent A-to-Z** | MMU Thin VIP — 왜 만들었나 → 어떻게 설계했나 → 결과 | **필수③ · 우대①** |
| 4 | ② 환경 구축·재사용 | Secure Boot UVM 리팩토링, OTP RAL 추상화 | 필수① · 업무③ |
| 5 | ③ 프로세스·Sign-off | 양산 sign-off, coverage closure 판단 | 필수② · 필수④ |
| 6 | 메모리 연관 | DRAM Controller LPDDR4/5, protocol timing SVA | 우대② |
| 7 | 기여 + 성장 | 단기 기여(즉시 Agent 개발) / 중장기(Mixed-Level 습득) | 갭 처리 |
| 8 | Why me | 3축 요약 + 조직 문장과의 연결 | — |

**슬라이드 3을 클라이맥스가 아니라 앞쪽에 두는 이유**: 10분 PT에서 면접관의 집중은 앞 3분에 몰린다. 공고가 두 번 강조한 항목을 뒤에 숨기면 그 3분을 낭비한다. DRAM 공고에서는 AI를 마지막 클라이맥스로 배치했지만, 여기서는 **가장 잘 맞는 카드를 먼저** 꺼낸다.

:::note[슬라이드 3의 3단 구성]
Custom Agent 슬라이드는 반드시 이 순서로 만든다.

1. **왜 만들었나** — 상용 VIP가 메모리 80%+ 점유·crash. *판단*의 근거
2. **어떻게 설계했나** — 필요한 데이터패스만 남긴 thin 설계, 계층 구조
3. **결과** — stress crash 0%, 통제권 확보

면접관이 듣고 싶은 것은 2번이 아니라 **1번**이다. 만들 줄 아는 사람은 많고, *만들지 말지 판단할 줄 아는 사람*은 적다. 자세한 서사는 [03 — Custom UVM Agent](../03_custom_uvm_agent/)와 [08 — 프로젝트 STAR](../08_project_star/)에서 다듬는다.
:::

## 5. 갭을 지원동기로 전환하기

Mixed-Level 경험 부재는 반드시 질문된다. 두 표현의 차이가 결과를 가른다.

- ❌ "Mixed 검증은 해본 적이 없습니다." → 공고 항목을 스스로 부정 = 자살골
- ❌ "비슷한 걸 해봤습니다." → 첫 꼬리질문에서 무너짐
- ✅ "Digital IP와 Subsystem 레벨은 **자체 Agent를 만들어 밑바닥부터** 검증해 왔습니다. **Schematic이 섞인 Full-Chip Mixed-Level은 아직** 직접 해보지 못했고, **그 축을 채우려고 지원했습니다.** MMU를 스펙만 보고 3개월 만에 환경째 세운 것처럼, 검증 대상이 바뀌어도 빠르게 도달하는 방식은 증명돼 있습니다."

이 답변의 구조는 네 부분이다.

1. **먼저 강점을 세운다** — 갭을 말하기 전에 겹치는 영역을 확정
2. **갭의 범위를 좁힌다** — "Mixed 전체"가 아니라 "Schematic이 섞인 Full-Chip Mixed-Level"
3. **지원동기로 연결한다** — 갭이 곧 지원 이유
4. **학습 속도의 증거를 붙인다** — 과거에 낯선 대상을 빠르게 흡수한 사례

갭을 무대에 스스로 올리지 마라. PT에서는 **성장 계획으로 1회**, Q&A에서는 **받아치기로 1회**. 그 이상 언급하면 면접관의 기억에 그것만 남는다.

:::caution[정직성]
"해봤다"고 넓히지 마라. Mixed-Level은 [06 — Mixed-Level 검증 & 갭 방어](../06_mixed_level_gap/)에서 *최소 지식*을 갖추되, 경험으로 포장하지 않는다. 경력 면접에서 과장은 두 번째 꼬리질문에서 반드시 드러난다.
:::

## 핵심 정리

- 조직 문장의 **3계층(Mixed IP / Digital IP / Subsystem·Top)** 과 "검증 시스템·모델 개발"이 질문 축을 미리 알려준다.
- 필수③과 우대①이 **같은 것을 두 번** 요구한다 — Custom UVM Agent A-to-Z가 면접의 무게중심이다.
- 갭은 **하나**(Mixed-Level). DRAM 공고의 비대칭 전략을 복사하지 말고 **정면승부**로 간다.
- 관통 메시지의 주어는 "메모리 경험"이 아니라 **"Agent를 밑바닥부터 세워 본 사람"**.
- 갭 답변은 *강점 확정 → 범위 축소 → 지원동기 연결 → 학습 속도 증거* 4단.

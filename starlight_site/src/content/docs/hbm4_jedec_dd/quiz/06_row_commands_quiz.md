## Q1. (Apply) ★

`tRP = 12 ns`, `tCK = 0.5 ns`다. `PREpb`를 T0(상승 에지)에 발행했을 때 후속 `ACTIVATE`의 가장 이른 슬롯은?

<details>
<summary>정답 / 해설</summary>

```
nRP = 0.5 × RU(2 × 12 / 0.5) = 0.5 × RU(48) = 0.5 × 48 = 24.0
```

T0 + 24.0 = **T24 (상승 에지)** — 정수이므로 하강 에지가 아니다. **예외 규칙 적용 불필요.**

**대조**: 만약 `tRP = 12.1 ns`였다면
```
nRP = 0.5 × RU(2 × 12.1 / 0.5) = 0.5 × RU(48.4) = 0.5 × 49 = 24.5
```
T24.5는 **하강 에지**이고 `ACTIVATE`는 상승 에지 전용이므로 **+0.5 → T25**.

**설계 함의**: 아날로그 값이 조금만 달라져도 예외 규칙 적용 여부가 갈린다. 라운딩 로직에 예외를 넣지 않으면 **특정 타이밍 조합에서만 위반이 나며 재현이 어렵다.**

</details>

## Q2. (Understand)

HBM4가 라운딩 공식을 `RU(t/tCK)`에서 `0.5 × RU(2·t/tCK)`로 바꾼 이유는?

<details>
<summary>정답 / 해설</summary>

HBM4는 **`PREpb`와 `PREab`를 상승·하강 양쪽 에지에서 발행**할 수 있게 했다(§6.3.2.4). 스케줄링 유연성이 생겼는데 라운딩 공식이 **상승 에지만 가정하면 그 유연성을 쓸 수 없다.**

새 공식은 **다음 상승 또는 하강 에지**로 올림하므로 결과가 전통 공식과 같거나 **0.5 nCK 작다.**

**적용 대상은 `tRAS`·`tRTP`·`tWR`·`tRP` 네 개뿐**이다.

**양방향 함정**:
- 전통 공식을 그대로 쓰면 규격 위반은 아니지만 **성능을 버린다.**
- 새 공식을 쓰면서 `tRP` 예외를 빠뜨리면 **하강 에지에 ACTIVATE를 발행하는 위반**이 된다.

</details>

## Q3. (Remember)

Refresh 다섯 갈래를 나열하고 각각이 RAA 카운트에 미치는 영향을 쓰라.

<details>
<summary>정답 / 해설</summary>

| 커맨드 | 대상 | RAA 효과 |
|---|---|---|
| `REFab` | 전 뱅크 | **− `RAADEC`** |
| `REFpb` | 단일 뱅크 | **− `RAADEC`** |
| `RFMab` | 전 뱅크 | **− `RAAIMT`** |
| `RFMpb` | 단일 뱅크 | **− `RAAIMT`** |
| `DRFMpb` | 단일 뱅크 (지목된 행의 이웃) | **감소 없음** |

감소는 모두 **하한 0**이며, 음수나 "pull-in"은 허용되지 않는다(§6.3.2.5.3).

`DRFMpb`가 RAA를 깎지 않는 이유는 그것이 **RFM의 보충(supplemental)** 이지 대체가 아니기 때문이다.

</details>

## Q4. (Analyze)

DRFM이 활성인 상태에서 뱅크 3에 `ACT`(DRFM=1) → `PRE` → `RFMpb`(뱅크 3)를 발행했다. 뱅크 3의 RAA는 어떻게 변하는가?

<details>
<summary>정답 / 해설</summary>

```
ACT (DRFM=1)  →  RAA += 1,  그리고 행 주소를 뱅크 3의 DRFM 레지스터에 캡처
PRE           →  RAA 변화 없음
RFMpb (뱅크3) →  유효 샘플이 있으므로 DRFMpb로 실행
                  → 캡처된 행의 인접 행 refresh
                  → ⚠️ RAA 감소 없음
```

**최종: RAA는 순증 +1.**

**함정**: "RFM 커맨드를 보냈으니 RAA가 `RAAIMT`만큼 줄었겠지"라고 가정하면 컨트롤러의 RAA 추적이 장치와 어긋난다. 그 상태로 계속 ACTIVATE를 발행하면 **장치 쪽 RAA가 먼저 `RAAMMT`에 도달해 ACTIVATE가 거부**된다.

**설계 결론**: `RFMpb` 발행 시 그 뱅크의 **DRFM 샘플 유효 여부를 함께 보고**, 유효하면 RAA를 깎지 않아야 한다.

</details>

## Q5. (Evaluate)

`DEVICE_ID`를 읽으니 `RFM = 1`, `ARFM = 0`이었다. 컨트롤러가 `MR8` OP[5:4]에 `10`을 프로그램하면?

<details>
<summary>정답 / 해설</summary>

Table 40에서 `RFM=1, ARFM=0, level=10`은 **Illegal**이다.

**근거**(Note 1): ARFM을 지원하지 않는 장치는 `MR8` OP[5:4]를 **RFU로 정의**하므로 유일하게 허용되는 값은 `00`이다. [04장](../../04_mode_registers/)의 "RFU 비트는 0으로 프로그램해야 한다"는 규칙과 같은 이야기다.

**올바른 동작**: `ARFM = 0`이면 `MR8` OP[5:4] = `00`으로 두고, `RAAIMT`/`RAAMMT`/`RAADEC`의 읽기 전용 값을 그대로 사용한다.

**설계 결론**: 부팅 시퀀스는 **`DEVICE_ID`를 먼저 읽고** 그 결과에 따라 `MR8` 값을 결정해야 한다. MR 이미지를 하드코딩하면 이 조합 검사를 건너뛴다.

**부가**: Note 2에 따르면 ARFM은 **`RFM = 0`으로 출하된 장치가 초기 설정을 재정의해 RFM을 켜는** 용도로도 쓸 수 있다.

</details>

## Q6. (Understand)

진리표(Table 33)에 나오지 않는 `ARFU` 신호는 어떻게 다뤄야 하는가?

<details>
<summary>정답 / 해설</summary>

> 커맨드 인터페이스는 예약된 DDR 입력 신호 `ARFU`를 포함하며, 이는 후속 진리표에서 생략되지만 **다른 AWORD 입력들과 함께 유효한 신호 레벨로 구동되어야 한다.** — §6.3

그리고 `ARFU`는 세 곳에 참여한다.

| 참여 | 근거 |
|---|---|
| **유효 레벨 구동** | §6.3 |
| **CA 패리티 계산** | §6.4.1 (대상: `R[9:0]` + `C[7:0]` + **`ARFU`** + `APAR`) |
| **AWORD MISR 샘플링** | §6.8 (19 신호 × 2 = 38비트 중 하나) |

정체는 §11.1에 있다 — **"Reserved for future use: AWORD의 미사용 마이크로범프"**.

**교훈**: **"기능이 없다"와 "다룰 필요가 없다"는 다르다.** 진리표만 보고 구현하면 세 곳에서 모두 틀린다.

</details>

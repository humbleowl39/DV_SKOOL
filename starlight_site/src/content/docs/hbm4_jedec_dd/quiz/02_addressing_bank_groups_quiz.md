## Q1. (Remember)

Table 4가 정의하는 세 가지 무효 주소 조합은?

<details>
<summary>정답 / 해설</summary>

1. **`RA[13:12] = 11`** (Note 5)
2. **`SID[1:0] = 11`** (Note 6)
3. **4Hi 구성에서 `SID[0] = 1`** (Note 8)

**설계 결론**: 주소 디코더가 이 조합을 **생성할 수 있는 매핑**이면 설계 결함이다. 발생 자체를 막고, 그래도 도달하면 즉시 드러나도록 검사를 둔다.

</details>

## Q2. (Understand)

SID는 층(die)을 선택하는 신호인가?

<details>
<summary>정답 / 해설</summary>

**아니다.** Table 4 Note 4는 SID가 **커맨드 실행에서 뱅크 주소 비트로 동작**한다고 규정한다.

즉 뱅크 인덱스는 **`{SID, BA[3:0]}`** 의 연접이며, 그래서 채널당 뱅크 수가 16 → 32 → 48 → 64로 늘어난다.

같은 주석에 덧붙는 한 줄이 더 중요하다 — **"특정 AC 타이밍 파라미터 또는 선택된 타이밍 파라미터의 변형이 SID에 연동될 수 있다."** 물리적으로 다른 die에 있으므로 타이밍이 달라질 수 있다는 뜻이고, 실제 사례가 [07장](../../07_column_commands/)의 `tCCDR`이다.

</details>

## Q3. (Apply)

`CA[4:0]`, prefetch 256비트일 때 PC당 페이지 크기를 계산하고, 물리적으로 열리는 행 크기와의 관계를 설명하라.

<details>
<summary>정답 / 해설</summary>

```
Page Size = 2^COLBITS × (Prefetch / 8)
          = 2^5 × (256 / 8)
          = 32 × 32
          = 1024 B = 1 KB          ✅ §2의 "PC당 1 KB"와 일치
```

그리고 Note 3에 한 줄이 더 있다 — **"RA의 MSB가 열린 2 KB 페이지의 절반을 선택한다."**

즉 **물리 행은 2 KB**이고 PC가 보는 논리 페이지는 그중 **1 KB 절반**이다. `RA[13]`이 그 절반을 고른다.

**설계 함의**: 행 버퍼 히트 판정을 `RA[13:0]` 전체로 할지 `RA[12:0]`으로 할지가 갈린다. 두 층위를 섞으면 히트/미스 판정이 어긋난다.

</details>

## Q4. (Analyze)

64뱅크 구성에서 뱅크 11과 뱅크 27에 연속 ACTIVATE를 발행한다. 어떤 타이밍 파라미터가 적용되는가?

<details>
<summary>정답 / 해설</summary>

Table 5 배정에서 **연속 8뱅크가 한 그룹**이다.
- 뱅크 8–15 → **Group B**
- 뱅크 24–31 → **Group D**

**다른 그룹**이므로 **`tRRDS`** (짧은 쪽)가 적용된다.

비트로 확인하면 그룹 인덱스는 `{SID, BA[3]}` 즉 뱅크 인덱스의 상위 비트다 [추론].
```
11 = 001011 → 그룹 001 = B
27 = 011011 → 그룹 011 = D
```

**대조**: 뱅크 11과 13이었다면 둘 다 Group B이므로 **`tRRDL`**(긴 쪽)이 적용된다. 스케줄러가 그룹을 번갈아 배치하면 같은 요청량에도 더 짧은 간격으로 발행할 수 있다.

</details>

## Q5. (Evaluate)

32 Gb die를 12-high로 쌓았다. 채널당 밀도·총 용량·뱅크 수·뱅크 그룹 수를 구하라.

<details>
<summary>정답 / 해설</summary>

```
총 밀도   = 32 Gb × 12       = 384 Gb
채널당    = 384 Gb / 32채널  =  12 Gb     ← Table 4와 일치
총 용량   = 384 Gb / 8       =  48 GB
```

**뱅크 수 — 여기가 함정이다.** 12-high는 `SID[1:0]`을 쓰지만 **`SID[1:0] = 11`이 무효**다(Note 6). 따라서 유효 SID 값은 **3개**이고:

```
뱅크 수    = 3 × 16 = 48 뱅크
뱅크 그룹  = 48 / 8 =  6 그룹  (A~F)
```

SID 폭이 2비트라고 해서 네 값을 모두 쓸 수 있는 것이 아니다.

</details>

## Q6. (Analyze)

§3.3의 간이 상태도만 보고 상태 머신을 구현하면 무엇이 빠지는가? 규격이 명시한 생략 항목을 근거로 답하라.

<details>
<summary>정답 / 해설</summary>

§3.3은 상태도가 그리지 **않은** 것을 스스로 나열한다.

- **둘 이상의 뱅크가 관여하는 상태 천이**
- IEEE1500 명령으로 MR을 적재하거나 테스트 기능을 실행할 때의 상호작용
- `RESET_n` LOW 또는 `HBM_RESET`으로 **임의 상태에서 즉시 reset으로 가는 천이**
- ECS, ECS 억제, DRFM, ECC Engine Test Mode
- DCA와 DCM
- Loopback Test Mode
- WDQS-to-CK Alignment Training
- Rx Offset Calibration Training

**가장 치명적인 것은 첫 항목이다.** 실제로는 뱅크마다 상태가 있고 서로 다른 상태에 있을 수 있으므로, **채널 단위 단일 FSM으로 모델링하면 처음부터 틀린다.**

두 번째로 중요한 것은 **비동기 리셋 진입** — FSM의 모든 상태에 그 경로가 있어야 하고, 그 경로는 `RESET_n`과 `HBM_RESET` **양쪽**에서 온다.

**요약**: 생략 목록은 그대로 **설계 위험 목록**이다.

</details>

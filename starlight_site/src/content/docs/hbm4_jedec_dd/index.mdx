## 이 코스가 답하려는 질문

"HBM을 안다"는 말에는 두 층이 있습니다. **무엇이 있는지 아는 것**과 **그것을 만들 수 있는 것**입니다.

앞의 층은 [HBM 아키텍처](../hbm/) 코스가 다룹니다 — 스택이 어떻게 쌓이고 채널이 어떻게 나뉘는지. 그런데 실제로 Base Die의 디지털 블록을 설계하거나, 컨트롤러 RTL을 짜거나, 스펙 기반으로 검증 계획을 세우려면 그것으로 부족합니다. **ACTIVATE 커맨드가 왜 1.5 사이클인지**, **뱅크 그룹이 왜 타이밍 파라미터를 둘로 가르는지**, **on-die ECC가 켜진 상태에서 MBIST가 무엇을 볼 수 있는지** — 이런 것들은 규격 조문에 있고, 그 조문 하나하나가 곧 설계 요구사항입니다.

이 코스는 **JESD270-4(HBM4) 규격을 조문 단위로 읽고**, 각 요구사항이 **어떤 로직을 강제하는가**까지 잇습니다. 관점은 검증이 아니라 **디지털 설계**입니다.

:::caution[인용과 저작권에 대하여]
본 자료는 **JESD270-4 (High Bandwidth Memory (HBM4) DRAM, JEDEC Solid State Technology Association, 2025-04)** 를 근거로 합니다.

- 본문의 인용은 **학습 목적의 요약·재구성·참조**이며 **스펙 원문의 복제가 아닙니다.** 표와 그림은 옮기지 않고 절·표·그림 **번호로 지시**합니다.
- 참조한 원문은 문서 속성상 **WIP draft**입니다. 최종 발행본 및 이후 개정(JESD270-4A 등)과 다를 수 있습니다.
- **정밀한 수치·타이밍·전기 파라미터는 항상 JEDEC 원문을 우선**하세요. 이 자료로 설계를 확정하지 마십시오.
- 규격 밖 영역(컨트롤러·PHY·DFI 구현)은 공개 자료를 근거로 하며 **[확인] / [추론] / [구현 의존]** 등급을 표기합니다.
:::

## 이 코스의 위치

DV SKOOL의 HBM 자료는 네 토픽으로 나뉩니다. 이 코스는 **가장 깊은 층**입니다.

| 토픽 | 질문 | 깊이 |
|---|---|---|
| [`hbm`](../hbm/) | HBM은 **무엇인가** | 구조 개괄 · 6장 |
| [`hbm_dv`](../hbm_dv/) | HBM을 **어떻게 검증하는가** | 검증 실무 · 12장 |
| **`hbm4_jedec_dd`** (이 코스) | 규격은 **무엇을 요구하고, 그것을 어떤 로직으로 구현하는가** | 규격 조문 + RTL · 12장 |

개괄 설명은 반복하지 않고 [`hbm`](../hbm/)으로, 검증 방법은 [`hbm_dv`](../hbm_dv/)로 링크합니다. 이 코스는 **조문과 구현**에만 집중합니다.

## 🎯 학습 목표

코스를 마치면 다음을 할 수 있습니다.

- **Interpret (이해)** JESD270-4의 조직·주소·커맨드 조문을 읽고 그것이 강제하는 설계 제약을 도출한다.
- **Calculate (적용)** 뱅크 그룹·SID·버스트 길이를 고려해 커맨드 간 최소 간격과 페이지·주소 매핑을 계산한다.
- **Design (창작)** 커맨드 디코더·refresh 스케줄러·parity 검사기·ECC 경로를 RTL 수준 구조로 설계한다.
- **Analyze (분석)** DBIac·lane repair·loopback MISR/LFSR가 데이터 경로에 삽입하는 지연과 상태를 추적한다.
- **Differentiate (분석)** REFab / REFpb / RFM / ARFM / DRFM 다섯 갈래의 목적과 발행 조건을 구분한다.
- **Evaluate (평가)** IEEE 1500 테스트 경로와 mission mode 동작의 상호작용이 만드는 설계 위험을 판단한다.
- **Justify (평가)** 규격이 vendor에게 열어둔 지점(base logic die, I/O 전압, ECC symbol)이 왜 열려 있는지 설명한다.

## 📋 사전 지식

- **디지털 설계 기본** — 동기 설계, FSM, 파이프라인, CDC, setup/hold
- **SystemVerilog** — `always_ff`, `interface`, `modport`, 파라미터화
- **DRAM 동작 원리** — activate/precharge/refresh, 뱅크·행·열. 부족하면 [DRAM / DDR](../dram_ddr/)
- **HBM 구조 개괄** — 스택·채널·pseudo-channel. 부족하면 [HBM 아키텍처](../hbm/)
- **선택** — JEDEC 스펙 독해 경험이 있으면 [DRAM JEDEC Deep-Dive](../dram_jedec_dv/)가 좋은 대조군입니다 (LPDDR5 기준)

## 💡 학습 팁

:::tip[규격을 읽는 법]
- **표의 주석(NOTE)을 먼저 읽으세요.** 본문보다 주석에 설계 제약이 더 많이 숨어 있습니다. 예를 들어 BL8의 8 UI를 구분하는 column 주소 비트가 장치로 전달되지 않는다는 사실은 Table 4의 주석에 있고, 이것 하나가 주소 디코더 구조를 결정합니다.
- **"may" / "shall" / "vendor specific"을 구분하세요.** 규격이 열어둔 자리가 곧 제품 차별화 지점입니다.
- **숫자보다 관계를 외우세요.** `tCCDS`와 `tCCDL`의 값이 아니라 *왜 둘로 갈리는지*가 설계 판단을 만듭니다.
:::

:::caution[흔한 오해]
- **"HBM4 = HBM3의 폭 두 배"** 가 아닙니다. 채널 수·뱅크 구성·refresh 관리·복구 체계가 모두 바뀝니다.
- **"Base die는 HBM의 필수 구성"** 이 아닙니다. 규격은 그것을 **요구하지도 금지하지도 않습니다**(§3). 그 열린 자리가 Custom HBM을 가능하게 합니다 — 01장에서 다룹니다.
- **"채널은 독립이니 하나만 이해하면 된다"** — 채널은 독립이지만 **pseudo-channel은 클럭을 공유**합니다(§3.1). 그 차이가 설계에서 갈립니다.
:::

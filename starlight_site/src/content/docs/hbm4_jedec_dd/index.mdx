## 이 코스가 답하려는 질문

"HBM을 검증한다"는 말에는 두 층이 있습니다. **환경을 짤 줄 아는 것**과 **무엇을 확인해야 하는지 아는 것**입니다.

앞의 층은 [`hbm_dv`](../hbm_dv/) 코스가 다룹니다 — Agent를 어떻게 만들고, VIP를 어디까지 믿고, V-Plan을 어떻게 굴리는지. 그런데 환경이 다 갖춰져도 남는 질문이 있습니다. **이 DUT에서 정확히 무엇이 깨질 수 있는가.**

그 답은 발명하는 것이 아니라 **규격에서 읽어내는 것**입니다. `tCCD`가 왜 세 갈래로 갈리는지 알면 그것이 곧 coverage cross 축이 됩니다. 패리티 오류가 나도 커맨드가 실행된다는 조문을 읽으면, scoreboard가 뱅크 상태를 어떻게 오염 처리해야 하는지가 나옵니다. `ERRTH` 임계값이 `CEs` 보고를 거른다는 한 줄은, **에러를 주입해도 안 보일 수 있다**는 관측성 문제를 예고합니다.

이 코스는 **JESD270-4(HBM4) 규격을 조문 단위로 읽고**, 각 요구사항에서 **실패 모드 → checker → coverage → stimulus** 를 도출합니다. 규격 조문을 검증 항목으로 옮기는 훈련입니다.

:::caution[인용과 저작권에 대하여]
본 자료는 **JESD270-4 (High Bandwidth Memory (HBM4) DRAM, JEDEC Solid State Technology Association, 2025-04)** 를 근거로 합니다.

- 본문의 인용은 **학습 목적의 요약·재구성·참조**이며 **스펙 원문의 복제가 아닙니다.** 표와 그림은 옮기지 않고 절·표·그림 **번호로 지시**합니다.
- 참조한 원문은 문서 속성상 **WIP draft**입니다. 최종 발행본 및 이후 개정(JESD270-4A 등)과 다를 수 있습니다.
- **정밀한 수치·타이밍·전기 파라미터는 항상 JEDEC 원문을 우선**하세요. 이 자료로 검증 기준값을 확정하지 마십시오.
- 규격 밖 영역(컨트롤러·PHY·DFI 구현)은 공개 자료를 근거로 하며 **[확인] / [추론] / [구현 의존]** 등급을 표기합니다.
:::

## 이 코스의 위치

DV SKOOL의 HBM 자료는 네 토픽으로 나뉩니다. 이 코스는 **가장 깊은 층**입니다.

| 토픽 | 질문 | 깊이 |
|---|---|---|
| [`hbm`](../hbm/) | HBM은 **무엇인가** | 구조 개괄 · 6장 |
| [`hbm_dv`](../hbm_dv/) | 검증 **환경을 어떻게 짜는가** | Agent·VIP·V-Plan·회귀 · 12장 |
| **`hbm4_jedec_dd`** (이 코스) | 규격이 **무엇을 검증하라고 요구하는가** | 조문 → checker·coverage·stimulus · 12장 |

두 코스의 경계는 분명합니다. `hbm_dv`는 **방법론**, 이 코스는 **대상 목록**입니다. 여기서 도출한 검증 항목을 저기서 배운 구조로 구현합니다. 방법론이 필요한 지점은 서술을 반복하지 않고 [`hbm_dv`](../hbm_dv/)로 링크합니다.

## 🎯 학습 목표

코스를 마치면 다음을 할 수 있습니다.

- **Interpret (이해)** JESD270-4의 조직·주소·커맨드 조문을 읽고 그것이 만드는 **실패 모드 목록**으로 옮긴다.
- **Calculate (적용)** 라운딩 규칙·뱅크 그룹·버스트 길이로 커맨드 간 최소 간격을 산출해 **checker의 기대값**으로 쓴다.
- **Construct (창작)** 조문 하나를 SVA · scoreboard · reference model · monitor 중 **성격에 맞는 수단**으로 옮긴다.
- **Derive (창작)** 규격이 남긴 자유도(설정 조합·vendor 선택)에서 **coverage 축과 bin**을 도출한다.
- **Differentiate (분석)** REFab / REFpb / RFM / ARFM / DRFM 다섯 갈래를 구분하고 각각을 별도 coverage 축으로 나눈다.
- **Evaluate (평가)** 규격이 준 관측 수단(`SEV` · `AERR` · `DERR` · IEEE 1500 로그)으로 **무엇을 볼 수 있고 무엇이 가려지는지** 판단한다.
- **Prioritize (평가)** 조문 근거로 V-Plan 항목의 우선순위와 서명 조건을 정한다.

## 📋 사전 지식

- **UVM 기본** — Agent·sequence·scoreboard의 역할 분담. 부족하면 [UVM](../uvm/)
- **SystemVerilog 검증 구문** — `property`/`sequence`, `covergroup`/`coverpoint`/`cross`
- **DRAM 동작 원리** — activate/precharge/refresh, 뱅크·행·열. 부족하면 [DRAM / DDR](../dram_ddr/)
- **HBM 구조 개괄** — 스택·채널·pseudo-channel. 부족하면 [HBM 아키텍처](../hbm/)
- **검증 환경 구성** — 병행하거나 먼저 보면 좋습니다: [`hbm_dv`](../hbm_dv/)
- **선택** — JEDEC 스펙 독해 경험이 있으면 [DRAM JEDEC Deep-Dive](../dram_jedec_dv/)가 좋은 대조군입니다 (LPDDR5 기준)

### 5번 소절의 고정 구조

| 소절 | 답하는 질문 | 산출물 |
|---|---|---|
| **a. 무엇이 깨질 수 있는가** | 조문이 금지한 것을 DUT나 컨트롤러가 어겼을 때의 증상 | 실패 모드 표 (절 번호 · 위반 형태 · 증상) |
| **b. 어떻게 잡는가** | 이 규칙은 assertion인가, scoreboard인가, reference model인가 | SVA · checker 코드 |
| **c. 무엇을 덮었다고 말할 수 있는가** | 이 조문에서 나오는 coverage 축과 bin | covergroup 코드 |
| **d. 어떻게 자극하는가** | 그 bin에 도달하려면 무엇을 발행해야 하는가 | sequence 골격 · 제약 |

b소절의 **수단 선택**이 이 코스에서 가장 중요한 훈련입니다. 규칙 20개를 assertion 20개로 옮기는 것은 답이 아닙니다 — 그 이유는 [`hbm_dv` Ch09](../hbm_dv/09_assertion_checker/)에서 다룹니다.

## 💡 학습 팁

:::tip[규격을 검증자로서 읽는 법]
- **조동사가 수단을 정합니다.** `shall`은 **assertion**(위반하면 버그), `may`는 **coverage 축**(둘 다 나와야 함), `vendor specific`은 **config 파라미터**(환경이 랜덤화해야 함). 이 세 갈래를 먼저 표시하며 읽으면 V-Plan이 거의 자동으로 나옵니다.
- **표의 주석(NOTE)을 먼저 읽으세요.** 본문보다 주석에 검사 조건이 더 많이 숨어 있습니다. 예를 들어 BL8의 8 UI를 구분하는 column 주소 비트가 장치로 전달되지 않는다는 사실은 Table 4의 주석에 있고, 이것 하나가 주소 비교 로직의 마스크를 결정합니다.
- **숫자보다 관계를 외우세요.** `tCCDS`와 `tCCDL`의 값이 아니라 *왜 둘로 갈리는지*가 coverage cross를 만듭니다.
- **"관측할 수 없는 것"을 표시하며 읽으세요.** 규격이 오류를 걸러내거나(`ERRTH`) 정보를 합치는(`AERR`이 어느 버스인지 알려주지 않음) 지점이 곧 검증 구멍입니다.
:::

:::caution[흔한 오해]
- **"상용 VIP를 사면 규격 쪽은 해결된다"** — 규격이 vendor에게 열어둔 자리(base logic die, I/O 전압, ECC symbol 구성)는 VIP가 채워주지 않습니다. 무엇이 열려 있는지 아는 것이 검증 계획의 출발점입니다.
- **"채널은 독립이니 한 채널만 검증하면 된다"** — 채널은 독립이지만 **pseudo-channel은 클럭·Mode Register·저전력 상태를 공유**합니다(§3.1.2). 공유 자원 경합은 한 채널 안에서만 나옵니다 — 01장에서 다룹니다.
- **"ECC가 있으니 데이터 오류는 안 나온다"** — on-die ECC는 오류를 **가립니다.** 게다가 `ERRTH` 임계값이 `CEs` 보고를 걸러내므로, 에러를 주입해도 관측되지 않을 수 있습니다 — 09장에서 다룹니다.
- **"규격대로 짰으면 통과한다"** — JESD270-4는 **장치와의 계약**만 정의합니다. 벤더 데이터시트와 PHY/DFI 사양이 더해져야 검증 기준이 완성됩니다 — 12장에서 다룹니다.
:::

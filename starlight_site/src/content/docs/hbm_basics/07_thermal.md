## 1. Why care? — 세 개의 실이 여기서 만난다

이 코스에서 열 이야기를 세 번 예고했습니다.

| 어디서 | 무엇을 |
|---|---|
| [01장](../01_dram_operation/) | 온도가 오르면 전하가 빨리 새므로 **refresh를 두 배로** 해야 한다 |
| [03장](../03_stacking_tsv/) | TSV 종횡비 때문에 die를 **50 µm로 갈아야** 하고, 그러면 열이 갇힌다 |
| [04장](../04_interposer/) | 프로세서 **위**에 쌓지 않는 첫 번째 이유가 열이다 |

이 셋이 하나의 고리를 이룹니다. 그리고 그 고리 때문에 **열이 성능 문제가 됩니다** — 단순한 신뢰성 문제가 아닙니다.

메모리가 뜨거워지면 느려집니다. 그것도 **대역폭이 직접 깎입니다.** 왜 그렇게 되는지, 그리고 그래서 무엇을 해야 하는지가 이 장의 내용입니다.

## 2. 직관 — 열은 나는 곳과 빠지는 길이 어긋나 있다

### 열은 어디서 나는가

전력을 쓰는 곳에서 열이 납니다. 스택에서 전력을 가장 많이 쓰는 곳은 어디일까요?

| 위치 | 전력 소비 |
|---|---|
| **Base die** | **가장 크다** — 수천 개의 I/O 드라이버, 인터페이스 로직, 관리 회로 |
| Core die | 상대적으로 작다 — 셀 어레이는 접근할 때만 전력을 쓴다 |

[05장](../05_stack_anatomy/)에서 base die가 인터페이스와 관리를 전담한다고 했습니다. 그 일이 전력을 쓰는 일입니다. 그리고 HBM4에서 base die가 **로직 공정으로 이동해 더 많은 로직을 담게 되면**, 이 쪽 전력은 더 커집니다.

### 열은 어디로 빠져야 하는가

방열판입니다. 그런데 방열판은 **스택 위쪽**에 있습니다.

여기서 어긋남이 생깁니다.

> **가장 뜨거운 곳(base die)이 방열판에서 가장 멀다.**

base die에서 난 열은 위에 쌓인 core die를 **전부 통과해서** 방열판까지 가야 합니다.

### 한 장 그림 — 열이 오르는 길

```d2
direction: up

BASED: "Base Die\n전력 최대 · 방열판에서 가장 멀다\n= 가장 뜨겁다" {
  style.fill: "#ffcdd2"; style.font-color: "#0A0F25"
}
BMP1: "µbump 층  —  열 저항" { style.fill: "#ffe0b2"; style.font-color: "#0A0F25" }
MIDD: "중간 core die 들\n아래에서 온 열이 지나간다" { style.fill: "#ffe0b2"; style.font-color: "#0A0F25" }
BMP2: "µbump 층  —  열 저항" { style.fill: "#ffe0b2"; style.font-color: "#0A0F25" }
TOPD: "최상단 core die\n방열판에 가장 가깝다 = 가장 시원하다" {
  style.fill: "#e8f5e9"; style.font-color: "#0A0F25"
}
SINK: "리드 · 방열판" { style.fill: "#e3f2fd"; style.font-color: "#0A0F25" }

BASED -> BMP1: "열"
BMP1 -> MIDD
MIDD -> BMP2
BMP2 -> TOPD
TOPD -> SINK: "여기서 빠져나간다"
```

**열이 위로 흐르는데, 가는 길에 µbump 층이 여러 겹 끼어 있습니다.** 층마다 열 저항이 붙습니다.

그래서 스택 안의 온도는 **아래가 뜨겁고 위가 시원한** 기울기를 갖습니다. 그리고 스택이 높아질수록 그 기울기가 커집니다.

## 3. 작은 예 — 적층이 열 경로를 어떻게 나쁘게 만드는가

실리콘 자체는 열을 꽤 잘 전달합니다. 문제는 **실리콘이 아닌 것들**입니다.

### 문제 ① — 접합면마다 저항이 붙는다

die와 die 사이에는 µbump가 있고, 그 사이 빈 공간은 접착 수지로 채웁니다. 이 층의 열전도는 실리콘보다 **훨씬 나쁩니다.**

```
16-high 스택에서 base die 의 열이 방열판까지 가려면
  → core die 16장을 통과
  → 그 사이 접합면 16겹을 통과   ← 여기가 병목
```

층 수가 늘면 **통과할 실리콘도 늘지만, 통과할 접합면도 같이 늡니다.** 그래서 스택 높이가 열 문제를 직접 악화시킵니다.

### 문제 ② — 얇아진 실리콘은 옆으로도 못 퍼뜨린다

[03장](../03_stacking_tsv/)에서 TSV 종횡비 때문에 die를 **700 µm에서 50 µm로** 갈아야 한다고 했습니다. 그 박막화가 열에 두 번 영향을 줍니다.

- **좋은 쪽** — 위아래로 통과할 두께가 얇아지므로 수직 방향 저항은 줄어든다
- **나쁜 쪽** — 옆으로 퍼뜨릴 **단면이 줄어든다**

두 번째가 중요합니다. 두꺼운 실리콘은 국소적으로 뜨거운 지점(hot spot)의 열을 **옆으로 퍼뜨려** 평준화합니다. 얇아지면 그 능력이 떨어져 **hot spot이 국소적으로 더 뜨거워집니다.**

:::caution[TSV가 여기서 도움이 된다]
[03장](../03_stacking_tsv/)에서 TSV를 **신호 배선**으로만 다뤘습니다. 그런데 TSV는 **구리**입니다. 구리는 실리콘보다 열을 더 잘 전달합니다.

그래서 TSV는 신호만 나르는 것이 아니라 **열도 위로 나릅니다.** 실제로 신호를 나르지 않는 **열 전용 TSV(dummy TSV)** 를 일부러 배치하기도 합니다 — 전기적으로는 아무 일도 하지 않고 열만 통과시키는 통로입니다.

즉 TSV는 열 문제를 만들기도 하고(박막화를 강제해서) 풀기도 합니다(수직 열 통로를 제공해서).
:::

### 문제 ③ — 옆에 프로세서가 있다

[04장](../04_interposer/)에서 HBM 스택과 프로세서를 인터포저 위에 **나란히** 놓았습니다. 그런데 프로세서는 시스템에서 가장 뜨거운 부품입니다.

둘이 같은 인터포저 위에, 같은 리드 아래에 있으므로 **프로세서의 열이 옆으로 흘러 HBM에 들어옵니다.**

그래서 HBM의 온도는 자기 자신이 쓰는 전력만으로 정해지지 않습니다. **옆에 있는 프로세서가 얼마나 바쁜지에도 달려 있습니다.**

## 4. 일반화 — 온도가 대역폭을 깎는 고리

### 고리를 따라가 보자

[01장](../01_dram_operation/)에서 본 사실 하나가 여기서 결정적으로 쓰입니다.

> 커패시터의 전하가 새는 속도는 **온도에 민감**하다. 그래서 온도가 높아지면 refresh 주기를 **더 짧게** 가져가야 한다. 통상 85 °C를 넘으면 `tREFI`를 **절반**으로 줄인다.

이것을 대역폭까지 이어 보면 이렇게 됩니다.

```
스택 온도 상승
  → 전하가 빨리 샌다
  → refresh 주기를 절반으로 (tREFI ↓)
  → REF 커맨드 발행 빈도 2배
  → tRFC 동안 뱅크가 멈추는 시간 2배
  → 실효 대역폭 감소            ← 성능이 깎인다
```

**열이 신뢰성 문제로 끝나지 않고 성능 문제가 되는 경로**가 이것입니다.

### 그리고 되먹임이 있다

한 걸음 더 가면 고리가 닫힙니다.

```
refresh 빈도 2배
  → refresh 는 ACT 를 반복하는 동작이므로 전력을 쓴다
  → 전력 증가
  → 온도 상승                    ← 출발점으로 돌아온다
```

**양의 되먹임 고리**입니다. 온도가 오르면 refresh가 늘고, refresh가 늘면 전력이 늘고, 전력이 늘면 온도가 오릅니다.

:::tip[이 고리가 폭주하지 않는 이유]
정상적인 시스템에서는 폭주하지 않습니다. 되먹임의 이득이 1보다 작기 때문입니다 — refresh 증가로 늘어나는 전력은 전체 전력의 일부이고, 냉각 설계가 그 증가분을 흡수합니다.

그러나 **여유가 줄어들면 위험해집니다.** 냉각이 부족하거나, 옆의 프로세서가 최대 부하로 돌거나, 스택이 높아 열 경로가 나쁘면 고리의 이득이 커집니다. 그래서 HBM 시스템은 **온도를 감시하고 필요하면 부하를 줄이는** 제어가 필수입니다.

여기가 다음 절의 출발점입니다.
:::

### 스택 높이의 진짜 상한

[05장](../05_stack_anatomy/)에서 스택을 높이면 **용량이 늘고 대역폭은 그대로**라고 했습니다. 그렇다면 용량이 필요한 만큼 계속 쌓으면 될까요?

열이 그것을 막습니다.

| 스택을 높이면 | 열 관점 |
|---|---|
| 통과할 접합면이 늘어난다 | 열 저항 ↑ |
| base die가 방열판에서 더 멀어진다 | 최고 온도 ↑ |
| die 수가 늘어 총 전력이 는다 | 발열량 ↑ |

**세 가지가 모두 나쁜 방향입니다.** 그래서 스택 높이의 실질적 상한은 용량 수요가 아니라 **열이 정합니다.**

이것이 [03장](../03_stacking_tsv/)에서 본 **하이브리드 본딩**이 중요한 이유이기도 합니다. µbump를 없애 접합면의 열 저항을 줄이면, **같은 냉각 조건에서 더 높이 쌓을 수 있습니다.**

## 5. 디테일 — 그래서 무엇을 하는가

### 규격이 온도 감시를 의무로 둔다

HBM4 규격은 온도에 대해 특이한 조문을 둡니다 — **호스트에게 의무를 부과**합니다.

> 호스트는 IEEE 1500 테스트 포트 명령 `TEMPERATURE`와 `CHANNEL_TEMPERATURE`를 통해 **동작 온도를 감시해야 한다.** 호스트는 또한 **`CATTRIP` 출력을 감시해야** 하며, 이는 어느 die든 접합 온도가 **영구 손상을 초래할 수 있는 파국 트립 지점**을 초과했음을 알린다. — HBM4 규격 §7.3 (요약)

두 가지를 짚어 둡니다.

**① "해야 한다"가 두 번 쓰였습니다.** 온도 감시는 권장이 아니라 요구사항입니다. 규격이 장치에게 요구하는 것이 아니라 **호스트에게** 요구하는 드문 경우입니다.

**② 감시 경로가 테스트 포트입니다.** [05장](../05_stack_anatomy/)에서 base die가 온도 감시를 담당한다고 했는데, 그 결과를 읽는 통로가 IEEE 1500 테스트 포트입니다. 이름은 "테스트"이지만 **정상 동작 내내 필요**합니다.

### `CATTRIP` — 지워지지 않는 경고

`CATTRIP`은 파국 온도 초과를 알리는 출력입니다. 성질이 하나 특이합니다 — **기능 리셋으로 지워지지 않습니다.**

```
파국 온도 초과 → CATTRIP 어서트
  → 리셋을 걸어도 남아 있다
  → 전원을 끊어야 지워진다
```

**왜 이렇게 만들었을까요?** 파국 온도는 **영구 손상**과 직결되기 때문입니다. 손상이 일어났을 가능성이 있다면 그 사실이 리셋으로 사라져서는 안 됩니다.

호스트가 리셋 후 `CATTRIP`을 읽고 "리셋했으니 깨끗하다"고 가정하면 **과열 이력을 놓칩니다.** 반대로 이 성질 덕분에 리셋을 거쳐도 사건을 추적할 수 있습니다.

### 완화 수단은 어느 지점에 작용하나

수단들을 고리의 어디에 작용하는지로 정리하면 이렇습니다.

| 수단 | 작용 지점 |
|---|---|
| **하이브리드 본딩** ([03장](../03_stacking_tsv/)) | 열 저항 — 접합면을 없앤다 |
| **열 전용 TSV** | 열 저항 — 수직 통로를 늘린다 |
| **2.5D 배치** ([04장](../04_interposer/)) | 발열 집중 — 프로세서 위를 피한다 |
| **스택 높이 제한** | 열 저항 + 발열량 |
| **확장 온도 범위(선택)** | 동작 범위 — 더 뜨거운 조건을 허용하되 **추가 refresh**를 대가로 |
| **온도 감시 + 부하 조절** | 고리 자체 — 온도가 오르면 호스트가 부하를 줄인다 |

마지막 항목이 규격이 요구하는 것이고, 나머지는 설계·패키징이 하는 일입니다.

:::caution[확장 온도 범위는 공짜가 아니다]
규격은 표준 온도 범위 외에 **확장 온도 범위**를 선택 사항으로 둡니다. 더 뜨거운 조건에서도 동작할 수 있다는 뜻이라 좋게 들리지만, 그 범위에서는 **추가 refresh 주기가 필요할 수 있습니다.**

즉 확장 온도 범위는 "더 뜨거워도 괜찮다"가 아니라 **"더 뜨거운 대신 대역폭을 더 내놓는다"** 입니다. §4의 고리를 그대로 타는 것입니다.
:::

## 6. 흔한 오해

:::caution[넷]
**① "열은 신뢰성 문제일 뿐 성능과는 무관하다"**
아닙니다. 온도가 오르면 refresh가 두 배가 되고, 그만큼 뱅크가 멈춰 **대역폭이 직접 깎입니다.**

**② "스택 위쪽이 가장 뜨겁다"**
반대입니다. 방열판이 위에 있으므로 **위가 시원하고 아래가 뜨겁습니다.** 그리고 가장 뜨거운 곳은 전력을 가장 많이 쓰는 **base die**이며, 그것이 방열판에서 **가장 멉니다.**

**③ "die를 얇게 갈면 열이 더 잘 빠진다"**
절반만 맞습니다. 수직 방향으로는 유리하지만, **옆으로 퍼뜨릴 단면이 줄어** hot spot이 국소적으로 더 뜨거워집니다.

**④ "HBM 온도는 HBM이 쓰는 전력으로 정해진다"**
아닙니다. 옆의 **프로세서 열이 흘러들어옵니다.** 같은 인터포저 위, 같은 리드 아래에 있기 때문입니다.
:::

## 7. 핵심 정리

- **가장 뜨거운 곳(base die)이 방열판에서 가장 멀다.** base die는 수천 개의 I/O 드라이버와 관리 로직 때문에 전력을 가장 많이 쓰고, 스택 최하단에 있다.
- 스택 안 온도는 **아래가 뜨겁고 위가 시원한** 기울기를 갖는다. 층이 늘면 기울기가 커진다.
- 열 경로를 나쁘게 만드는 것은 실리콘이 아니라 **접합면**이다. die 사이 µbump 층마다 열 저항이 붙고, **층 수와 함께 늘어난다.**
- **박막화는 양날이다** — 수직 저항은 줄지만 **옆으로 퍼뜨릴 단면이 줄어** hot spot이 국소적으로 심해진다.
- **TSV는 열도 나른다.** 구리이므로 실리콘보다 열전도가 좋고, 신호를 나르지 않는 **열 전용 TSV**를 배치하기도 한다. TSV는 열 문제를 만들기도(박막화 강제) 풀기도(수직 통로) 한다.
- **옆의 프로세서 열이 흘러들어온다.** 2.5D 배치의 대가이며, HBM 온도는 자기 전력만으로 정해지지 않는다.
- ★ **고리** — 온도 ↑ → 전하 누설 ↑ → `tREFI` 절반 → REF 빈도 2배 → 뱅크 정지 시간 2배 → **실효 대역폭 감소.** 열이 성능 문제가 되는 경로다.
- 그리고 **되먹임** — refresh 증가는 전력 증가이고, 전력 증가는 온도 상승이다. 정상 조건에서는 폭주하지 않지만 **여유가 줄면 위험**하다.
- **스택 높이의 실질적 상한은 용량 수요가 아니라 열이 정한다.** 층이 늘면 열 저항·최고 온도·총 발열이 모두 나빠진다. 그래서 **하이브리드 본딩**이 더 높은 스택을 가능하게 한다.
- 규격은 **온도 감시를 호스트의 의무**로 규정한다(§7.3) — `TEMPERATURE` · `CHANNEL_TEMPERATURE` · `CATTRIP`. 경로는 **IEEE 1500 테스트 포트**이며, 이름과 달리 **정상 동작 내내 필요**하다.
- **`CATTRIP`은 기능 리셋으로 지워지지 않는다.** 파국 온도가 영구 손상과 직결되므로, 그 사실이 리셋으로 사라지면 안 되기 때문이다.
- **확장 온도 범위는 공짜가 아니다** — 더 뜨거운 조건을 허용하는 대신 **추가 refresh**를 대가로 치른다.

## 코스를 마치며

일곱 장을 관통한 것을 네 문장으로 정리하면 이렇습니다.

**하나 — DRAM의 지연은 동작이고, 대역폭은 구조다.**
셀에서 값을 꺼내는 데 걸리는 시간은 센스앰프가 전하 차이를 키우는 **물리적 동작 시간**이며 배선을 짧게 해서 줄일 수 없습니다([01](../01_dram_operation/)·[06장](../06_read_journey/)). 그래서 지연은 수십 년간 그대로였고, 개선된 것은 **동시에 얼마나 많이 진행할 수 있는가** — 즉 구조였습니다.

**둘 — HBM은 빠른 메모리가 아니라 가까운 메모리이고, 가깝기 때문에 넓다.**
핀당 전송률은 GDDR보다 **낮습니다.** 대역폭은 **폭**에서 나오고, 그 폭은 거리를 줄여서 얻었습니다([02장](../02_memory_wall/)). 거리를 줄이는 두 수단이 **위로 쌓기**([03장](../03_stacking_tsv/))와 **옆에 놓기**([04장](../04_interposer/))였습니다.

**셋 — 그런데 거리를 줄인 이득은 지연이 아니었다.**
전파 지연은 애초에 병목이 아니었습니다 — 인터포저 5 mm는 약 0.03 ns이고 전체 지연은 수십 ns입니다([06장](../06_read_journey/)). 얻은 것은 **비트당 에너지**와 **배선을 촘촘히 놓을 수 있는 여유**이고, 그 여유가 2,048비트 버스를 가능하게 했습니다.

**넷 — 모든 이득에 대가가 있고, 그 대가가 다시 성능으로 돌아온다.**
쌓으려면 얇게 갈아야 하고([03장](../03_stacking_tsv/)), 얇으면 열이 갇히고, 열이 갇히면 refresh가 두 배가 되어 **대역폭을 잃습니다**(이 장). HBM 설계는 이 고리를 관리하는 일이기도 합니다.

## 1. Why care? — 층 사이를 무엇으로 잇는가

[02장](../02_memory_wall/)에서 "거리를 줄이면 된다"까지 왔습니다. die를 위로 쌓으면 층 사이 거리가 **수십 µm**로 줄어듭니다.

그런데 여기서 당연한 질문이 생깁니다. **위층 회로와 아래층 회로를 무엇으로 연결하나요?**

전통적인 방법은 **와이어 본딩**입니다. die 가장자리의 패드에서 금선을 빼서 패키지 기판에 붙입니다. 실제로 NAND 플래시는 이 방식으로 여러 장을 쌓습니다 — 계단식으로 조금씩 밀어 쌓아 각 층의 가장자리가 노출되게 하고, 거기서 선을 뺍니다.

이 방식으로 HBM을 만들면 어떻게 될까요?

- 신호는 die 가장자리로 나와서, 금선을 타고 **패키지 기판까지 내려가고**, 다시 올라가야 합니다. **거리를 줄인 의미가 사라집니다.**
- 그리고 결정적으로, **선을 놓을 자리가 부족합니다.** 가장자리에 놓을 수 있는 패드 수에는 상한이 있습니다.

두 번째 문제가 더 근본적입니다. 그 이유를 보는 것이 이 장의 출발점입니다.

## 2. 직관 — 주변부가 아니라 면적을 쓴다

칩에서 신호를 빼는 방법은 두 가지입니다.

| 방식 | 신호를 빼는 곳 | 개수의 상한이 정해지는 방식 |
|---|---|---|
| **가장자리 패드** (와이어 본딩 등) | die의 **테두리** | 테두리 **길이**에 비례 |
| **관통 배선 (TSV)** | die의 **면 전체** | die **면적**에 비례 |

이 차이가 결정적입니다. 사각형 die의 한 변을 `L`이라고 하면,

```
테두리 길이 = 4L        →  L 에 비례해서 늘어난다
면적       = L²         →  L 의 제곱으로 늘어난다
```

die가 커질수록 **면적이 테두리보다 훨씬 빠르게** 늘어납니다. 그래서 신호를 많이 빼려면 **면을 써야** 합니다.

**TSV(Through-Silicon Via)** 는 그 면을 쓰는 방법입니다. 이름 그대로 **실리콘을 관통하는 통로(via)** 입니다. die 아무 지점에나 수직 구멍을 뚫고 도체를 채워서, 위쪽 면과 아래쪽 면을 직접 잇습니다.

### 한 장 그림 — 신호가 층을 오르는 길

```d2
direction: down

HOST: "호스트 (프로세서)" { style.fill: "#e3f2fd"; style.font-color: "#0A0F25" }

BASE: "Base Die  (스택 최하단)\n호스트와 마주보는 층" { style.fill: "#bbdefb"; style.font-color: "#0A0F25" }

B1: "µbump  —  die 사이 접합" { style.fill: "#ffe0b2"; style.font-color: "#0A0F25" }
D1: "DRAM die 1\nTSV 가 이 die 를 관통한다" { style.fill: "#e8f5e9"; style.font-color: "#0A0F25" }

B2: "µbump" { style.fill: "#ffe0b2"; style.font-color: "#0A0F25" }
D2: "DRAM die 2\nTSV 관통" { style.fill: "#e8f5e9"; style.font-color: "#0A0F25" }

B3: "µbump" { style.fill: "#ffe0b2"; style.font-color: "#0A0F25" }
D3: "DRAM die 3  (최상단)\nTSV 불필요 — 더 올라갈 곳이 없다" { style.fill: "#c8e6c9"; style.font-color: "#0A0F25" }

HOST -> BASE: "인터포저 경유 · 04장"
BASE -> B1
B1 -> D1
D1 -> B2: "TSV 를 지나 위로"
B2 -> D2
D2 -> B3: "TSV 를 지나 위로"
B3 -> D3
```

읽는 법이 셋입니다.

1. **신호는 아래에서 위로 올라갑니다.** 호스트와 마주보는 것은 최하단 base die 하나뿐이고, 위층으로 가는 모든 신호는 아래층을 **관통**해서 갑니다.
2. **TSV는 die 안을, µbump는 die 사이를 잇습니다.** 둘은 다른 것입니다 — TSV는 실리콘을 뚫고 지나는 세로 배선, µbump는 두 die를 물리적·전기적으로 붙이는 접점입니다.
3. **최상단 die에는 TSV가 필요 없습니다.** 더 위로 올려보낼 신호가 없기 때문입니다. 그래서 최상단 die는 다른 층과 구조가 조금 다릅니다.

## 3. 작은 예 — 테두리로는 왜 안 되는가

숫자를 대 봅시다. HBM4 스택 하나가 호스트와 주고받는 신호는 **약 3,900개**입니다 (채널당 120 × 32채널 + 전역 56 = 3,896) **[추론 — 규격의 신호 목록에서 계산]**.

이 신호들이 스택 안에서 여러 층으로 갈라져 올라가야 합니다.

**만약 테두리에 패드를 놓는다면**

DRAM die 한 변이 대략 **10 mm** 라고 하고, 고속 신호 패드를 **40 µm 간격**으로 놓을 수 있다고 하면 **[개략]**,

```
테두리 전체 길이 = 4 × 10 mm = 40 mm = 40,000 µm
놓을 수 있는 패드 = 40,000 ÷ 40 = 1,000 개
```

**1,000개**입니다. 그런데 3,900개가 필요합니다. **네 배 부족합니다.** 게다가 이건 테두리를 빈틈없이 쓴다는 비현실적 가정이고, 실제로는 전원·접지 패드도 같은 자리를 다퉈야 합니다.

**면적을 쓴다면**

같은 die의 면적에 TSV를 **50 µm 간격**의 격자로 놓는다고 하면 **[개략]**,

```
면적 = 10 mm × 10 mm = 100 mm²
격자 한 칸 = 50 µm × 50 µm = 0.0025 mm²
놓을 수 있는 자리 = 100 ÷ 0.0025 = 40,000 개
```

**40,000개**입니다. 필요한 3,900개의 **10배**입니다. 실제로는 회로가 자리를 차지하니 TSV에 면적 전체를 줄 수 없지만, **여유가 자릿수 단위로 다릅니다.**

:::tip[이것이 "폭으로 푼다"가 가능해진 이유다]
[02장](../02_memory_wall/)에서 *"2048개의 선을 놓을 자리가 없었다"* 고 했습니다. 그 자리를 만든 것이 **면적을 쓰는 결정**입니다.

테두리는 die가 커져도 선형으로만 늘어나지만, 면적은 제곱으로 늘어납니다. 신호 수를 자릿수 단위로 늘리려면 면을 써야 하고, 면을 쓰려면 **수직으로 관통**해야 합니다.
:::

## 4. 일반화 — TSV의 구조와 전기적 성질

### 구조 — 그냥 구멍이 아니다

TSV는 실리콘에 뚫은 구멍에 도체를 채운 것이지만, 그것만으로는 동작하지 않습니다. 실리콘은 **절연체가 아니라 반도체**이기 때문입니다. 도체를 그대로 채우면 신호가 주변 실리콘으로 새어 나가고, 다른 TSV와 간섭합니다.

그래서 안쪽부터 이런 층 구조를 갖습니다 **[개략 — 벤더별 구성 차이 있음]**.

| 층 | 역할 |
|---|---|
| **도체** (보통 구리) | 신호가 지나는 통로 |
| **배리어** | 구리 원자가 실리콘으로 확산되는 것을 막는다 |
| **절연막** (보통 산화막) | 도체를 주변 실리콘에서 전기적으로 격리한다 |

여기서 중요한 결과가 나옵니다 — **도체와 실리콘 사이에 절연막이 끼어 있으면, 그것은 커패시터입니다.** 이 기생 커패시턴스가 TSV의 주된 전기적 부담이 됩니다.

### 전기적으로는 아주 좋은 배선이다

TSV를 PCB 배선과 비교하면 이렇습니다.

| | PCB 배선 | TSV |
|---|---|---|
| 길이 | 수 cm | **수십 µm** — 1,000배 짧다 |
| 단면 | 얇고 넓적한 띠 | **굵은 기둥** (지름 5~10 µm) **[개략]** |
| 저항 | 길이에 비례해 큼 | 짧고 굵어서 **작다** |
| 인덕턴스 | 큼 | **작다** |
| 주된 기생 성분 | 저항·인덕턴스·유전 손실 | **커패시턴스** (수십~수백 fF 수준) **[개략]** |

[02장](../02_memory_wall/)에서 본 세 가지 문제 — 감쇠, 번짐(ISI), 반사 — 는 모두 **배선이 길기 때문**에 생겼습니다. TSV는 1,000배 짧으므로 그 문제들이 사실상 사라집니다.

그래서 **TSV 구간에서는 신호 속도가 병목이 아닙니다.** 대신 커패시턴스를 구동하는 만큼의 전력만 들고, 그 값이 작으므로 **비트당 에너지가 매우 낮습니다.** 이것이 HBM이 낮은 전송률로도 큰 대역폭을 낼 수 있는 물리적 근거입니다.

### 왜 die를 얇게 갈아야 하는가

TSV에는 제조상 제약이 하나 있습니다 — **종횡비(aspect ratio)**, 즉 깊이 ÷ 지름의 한계입니다. 너무 깊고 가는 구멍은 균일하게 뚫고 채울 수 없습니다. 현실적인 상한이 대략 **10:1 안팎**입니다 **[개략]**.

이 제약이 die 두께를 결정합니다.

```
TSV 지름을 5 µm 로 하고, 종횡비 상한을 10:1 이라고 하면
  뚫을 수 있는 최대 깊이 = 5 × 10 = 50 µm
  → die 두께가 50 µm 이하여야 한다
```

그런데 웨이퍼에서 갓 나온 die는 **700 µm 이상**입니다 **[개략]**. 그대로라면 지름 5 µm 구멍의 종횡비가 **140:1** — 불가능합니다.

**결론: 쌓으려면 die를 갈아서 얇게 만들어야 합니다.** 통상 **수십 µm** 수준입니다.

:::caution[이 한 줄이 이 코스의 뒤쪽 절반을 만든다]
"die를 50 µm로 갈아야 한다"는 요구는 단순한 공정 사항이 아닙니다. 세 가지가 여기서 파생됩니다.

| 파생 문제 | 다루는 곳 |
|---|---|
| 얇은 die는 **기계적으로 취약**하다 — 휘고 깨진다 | 이 장 §5 |
| 얇은 die 여러 장이 붙어 있으면 **열이 갇힌다** | [07장](../07_thermal/) |
| 실리콘 자체가 얇아지면 **열이 옆으로 퍼지기도** 어렵다 | [07장](../07_thermal/) |

**"쌓으려면 얇게 → 얇으면 열이 문제"** — 이 고리가 HBM 설계 전체를 관통합니다.
:::

## 5. 디테일 — TSV가 치르는 대가

### ① 면적을 먹는다

TSV는 그 자리에 회로를 놓을 수 없게 만듭니다. 구멍 자체의 면적뿐 아니라 **주변에 회로를 두면 안 되는 영역**(keep-out zone)이 따라옵니다. 구멍을 뚫고 금속을 채우면 주변 실리콘에 응력이 걸려 트랜지스터 특성이 변하기 때문입니다.

그래서 TSV를 많이 놓을수록 **저장할 수 있는 셀이 줄어듭니다.** 대역폭과 용량 사이의 맞바꿈입니다.

### ② 얇은 die는 다루기 어렵다

50 µm는 사람 머리카락 굵기보다 얇습니다. 이 두께의 실리콘은 유연하지만 잘 깨집니다. 그래서 갈고 옮기고 붙이는 모든 단계에서 **수율 위험**이 생깁니다.

이것이 [02장](../02_memory_wall/)에서 말한 *"거리를 줄이는 대가"* 의 실체 중 하나입니다. HBM이 비싼 이유이기도 합니다.

### ③ 접합부가 새로운 고장 지점이 된다

die와 die를 붙이는 접점(µbump)이 층마다 필요합니다. 스택이 높아지면 접점 수가 그만큼 늘고, **하나라도 불량이면 그 신호선이 끊깁니다.**

규모를 생각해 보면 이것이 왜 심각한지 보입니다 — 스택 하나에 신호 접점이 **수천 개**이고, 층마다 반복됩니다. 통계적으로 결함이 **반드시** 생깁니다.

그래서 HBM 규격은 **여분 신호선과 복구 수단**을 명시적으로 배정합니다. 불량 레인을 끄고 여분 레인으로 밀어내는 구조입니다. 상세는 [`hbm4_jedec_dd` Ch10](../../hbm4_jedec_dd/10_test_repair/)에 있습니다.

:::tip[리던던시는 선택 기능이 아니다]
이 규모에서 "전부 정상"을 기대할 수 없으므로, **복구 기능은 있으면 좋은 것이 아니라 반드시 있어야 하는 것**입니다. HBM이 처음부터 복구 수단을 규격에 넣은 이유입니다.
:::

### µbump를 없애는 방향 — 하이브리드 본딩

µbump는 접점이면서 동시에 **간격을 만드는 것**이기도 합니다. 범프가 있으면 die 사이에 그만큼 틈이 생기고, 그 틈이 열 전달을 방해합니다.

그래서 최근 방향은 범프를 없애고 **구리 면을 직접 맞붙이는** 것입니다 — **하이브리드 본딩**이라고 부릅니다. 얻는 것이 둘입니다.

- 접점 간격을 더 좁힐 수 있다 → **더 많은 연결**
- die 사이 틈이 없어진다 → **열이 더 잘 빠진다**

이 방향이 스택을 더 높이 쌓는 것을 가능하게 합니다. 다만 공정 난이도가 크게 올라갑니다.

## 6. 흔한 오해

:::caution[넷]
**① "TSV는 그냥 세로 배선이다"**
배선이긴 하지만, 그 존재가 **die를 얇게 갈아야 한다는 요구**를 만들고(종횡비), 그것이 다시 **기계적 취약**과 **열 문제**로 이어집니다. TSV를 배선으로만 보면 이 연쇄가 보이지 않습니다.

**② "TSV와 µbump는 같은 것이다"**
다릅니다. **TSV는 die 안을 관통**하는 세로 배선이고, **µbump는 die 사이를 붙이는** 접점입니다. 신호는 둘을 번갈아 지납니다.

**③ "모든 die에 TSV가 있다"**
**최상단 die에는 필요 없습니다.** 더 위로 올려보낼 신호가 없기 때문입니다.

**④ "TSV가 많으면 좋다"**
면적을 먹습니다. TSV를 늘리면 셀을 놓을 자리가 줄어 **용량이 깎입니다.** 대역폭과 용량의 맞바꿈이며, 무조건 많을수록 좋은 것이 아닙니다.
:::

## 7. 핵심 정리

- **TSV(Through-Silicon Via)** 는 실리콘 die를 수직으로 관통하는 배선이다. die의 **면 전체**를 신호 통로로 쓸 수 있게 한다.
- ★ 핵심은 **주변부 대신 면적을 쓴다**는 것이다. 테두리는 die 크기에 **비례**해 늘지만 면적은 **제곱**으로 는다. 신호 수를 자릿수 단위로 늘리려면 면을 써야 한다.
- 계산으로 확인 — 테두리 패드로는 약 **1,000개**, 면적에 TSV를 놓으면 약 **40,000개** 규모 **[개략]**. 필요한 것은 약 3,900개.
- TSV는 **도체 + 배리어 + 절연막** 구조다. 절연막 때문에 **기생 커패시턴스**가 주된 전기적 부담이 된다.
- 전기적으로는 **아주 좋은 배선**이다 — PCB보다 1,000배 짧아 감쇠·번짐·반사가 사실상 없다. 그래서 **비트당 에너지가 매우 낮다.** 이것이 낮은 전송률로 큰 대역폭을 내는 근거다.
- **종횡비 상한(약 10:1)** 이 die 두께를 정한다 — 지름 5 µm면 깊이 50 µm까지. 그래서 **수백 µm 두께의 die를 수십 µm로 갈아야** 한다.
- 대가가 셋 — **면적**(용량과 맞바꿈), **기계적 취약**(수율), **접합부 고장**(그래서 규격이 복구 수단을 배정한다).
- **µbump는 die 사이를 잇는 접점**이고 TSV와 다르다. 범프를 없애는 **하이브리드 본딩**이 더 촘촘한 연결과 더 나은 열 전달을 준다.
- ★ **"쌓으려면 얇게 → 얇으면 열이 문제"** — 이 고리를 [07장](../07_thermal/)에서 마무리한다.

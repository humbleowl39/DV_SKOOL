## 1. Why care? — 스택은 이어졌는데, 프로세서까지는?

[03장](../03_stacking_tsv/)에서 스택 내부가 이어졌습니다. TSV가 die를 관통하고 µbump가 die 사이를 붙입니다.

그런데 아직 남은 구간이 있습니다. **스택과 프로세서 사이**입니다.

신호가 약 **3,900개**입니다. 이걸 일반적인 방법 — 스택을 보드에 붙이고 프로세서도 보드에 붙여서 PCB 배선으로 잇는 방법 — 으로 처리할 수 있을까요?

[02장](../02_memory_wall/)에서 *"2048개의 선을 놓을 자리가 없었다"* 고 했습니다. 03장은 **스택 안쪽**의 자리 문제를 면적으로 풀었습니다. 이제 **스택 밖**의 자리 문제가 남았고, 이 장이 그것을 다룹니다.

먼저 정말 안 되는지 숫자로 확인합니다.

## 2. 직관 — 문제는 배선 밀도다

핵심은 **선 하나를 얼마나 가늘게, 얼마나 촘촘하게 놓을 수 있는가**입니다.

| 기판 | 최소 선폭·간격 | 만드는 방식 |
|---|---|---|
| **일반 PCB** | 약 **50 µm** **[개략]** | 구리 박막을 화학적으로 식각 |
| 고급 HDI PCB | 약 **25~40 µm** **[개략]** | 같은 방식, 정밀도 향상 |
| **실리콘 인터포저** | 약 **1 µm** 급 **[개략]** | **반도체 공정**으로 금속층을 만든다 |

**50배 이상 차이**입니다. 그리고 이 차이의 원인은 단순합니다 — **PCB는 기판 산업의 공정으로, 인터포저는 반도체 공정으로 만듭니다.** 반도체 공정은 나노미터를 다루므로 마이크로미터 배선은 여유롭습니다.

그래서 해법이 이렇게 정리됩니다.

> **기판을 실리콘으로 바꾼다.** 프로세서와 HBM 스택을 그 실리콘 판 위에 나란히 놓고, 판 안의 미세 배선으로 잇는다.

이 실리콘 판을 **인터포저(interposer)** 라고 부릅니다. "사이에 끼워 넣는 것"이라는 뜻입니다.

### 한 장 그림 — 층층이 쌓인 구조

```d2
direction: down

ONINT: "인터포저 위 (2.5D)" {
  style.fill: "#f5f5f5"; style.font-color: "#0A0F25"

  CPU: "프로세서 die" { style.fill: "#e3f2fd"; style.font-color: "#0A0F25" }
  HBM: "HBM 스택\n(03장)" { style.fill: "#e8f5e9"; style.font-color: "#0A0F25" }

  CPU -> HBM: "약 3,900 신호 — 여기서 직결"
}

INT: "실리콘 인터포저\n미세 배선 약 1 µm 급 · 자체 TSV 보유" {
  style.fill: "#bbdefb"; style.font-color: "#0A0F25"
}
C4: "C4 범프  ·  약 150 µm 피치" { style.fill: "#ffe0b2"; style.font-color: "#0A0F25" }
PKG: "패키지 기판" { style.fill: "#eceff1"; style.font-color: "#0A0F25" }
BGA: "BGA 볼  ·  약 0.5~1 mm 피치" { style.fill: "#ffe0b2"; style.font-color: "#0A0F25" }
PCB: "메인보드" { style.fill: "#eceff1"; style.font-color: "#0A0F25" }

ONINT -> INT: "µbump · 약 40 µm 피치"
INT -> C4: "전원과 프로세서 외부 I/O 만 내려간다"
C4 -> PKG
PKG -> BGA
BGA -> PCB
```

이 그림에서 **가장 중요한 것은 `INT -> C4` 화살표의 라벨**입니다. 광폭 버스는 **아래로 내려가지 않습니다.** 인터포저 안에서 프로세서와 HBM이 직접 이어지고 끝납니다.

## 3. 작은 예 — PCB로 하면 얼마나 필요한가

3,900개의 신호를 PCB에 배선한다고 해 봅시다.

고속 병렬 신호선은 **선 하나 놓고 옆에 접지선을 두는** 식으로 간격을 확보해야 합니다. 신호선 하나가 실질적으로 차지하는 폭을 **선폭 50 µm + 간격 50 µm = 100 µm** 로 잡습니다 **[개략]**.

**한 층에 모두 놓는다면**

```
필요한 폭 = 3,900 × 100 µm = 390,000 µm = 390 mm
```

**39 cm**입니다. 프로세서 패키지 한 변이 보통 5~8 cm인데, 배선을 빼려면 그 폭이 39 cm 필요합니다. **불가능합니다.**

**층을 나눠 쌓는다면**

한 층에 100 mm 폭을 쓸 수 있다고 하면 층당 1,000개, 즉 **4개 층**이 필요합니다. 그런데 고속 신호층 사이에는 접지층을 끼워야 하므로 실제로는 **8~10개 층**이 됩니다. 게다가

- 층이 다르면 **비아**로 옮겨야 하고, 비아마다 임피던스가 흐트러집니다
- 3,900개의 **길이를 서로 맞춰야** 합니다
- 층이 늘어날수록 기판 두께·비용·수율이 나빠집니다

**인터포저로 하면**

선 하나가 차지하는 폭을 **선폭 1 µm + 간격 1 µm = 2 µm** 로 잡으면 **[개략]**,

```
필요한 폭 = 3,900 × 2 µm = 7,800 µm = 7.8 mm
```

**7.8 mm**입니다. 프로세서 die 한 변보다 짧습니다. **한 층으로 충분**하고, 실제로는 몇 개 층을 써서 더 여유 있게 배치합니다.

| | PCB | 실리콘 인터포저 |
|---|---|---|
| 3,900개에 필요한 폭 (1층) | **390 mm** | **7.8 mm** |
| 현실적 층 수 | 8~10 (접지층 포함) | 2~4 |
| 배선 길이 | 수 cm | **수 mm** |

**50배의 밀도 차이가 "불가능"과 "여유"를 가릅니다.** 그리고 배선이 짧아지므로 [02장](../02_memory_wall/)의 두 벽도 함께 물러납니다.

## 4. 일반화 — 피치의 계단, 그리고 광폭 버스가 가지 않는 곳

### 피치는 단계별로 커진다

die 내부에서 메인보드까지, 접점 간격이 **자릿수 단위로 계단을 오릅니다** **[개략]**.

| 구간 | 접점 | 피치 | 규모 |
|---|---|---|---|
| die 내부 배선 | — | nm ~ 수백 nm | — |
| die ↔ die (스택 내부) | **µbump** | 약 **40 µm** | 수천 개 |
| die ↔ 인터포저 | **µbump** | 약 **40 µm** | 수천 개 |
| 인터포저 ↔ 패키지 기판 | **C4 범프** | 약 **150 µm** | 수천 개 |
| 패키지 ↔ 메인보드 | **BGA 볼** | 약 **0.5~1 mm** | 수천 개 |

각 단계가 **3~10배씩** 커집니다. 이유는 아래로 갈수록 **다루는 공정이 거칠어지고, 열팽창 차이로 인한 기계적 응력을 흡수해야** 하기 때문입니다. 작은 접점은 정밀하지만 응력에 약합니다.

여기서 자연스러운 결론이 나옵니다 — **µbump 피치(40 µm)에서 BGA 피치(500 µm 이상)로 한 번에 뛸 수 없습니다.** 중간에 단계를 놓아 주는 것이 필요하고, 인터포저가 그 역할도 합니다.

### 하지만 진짜 요점은 다른 데 있다

인터포저가 피치를 변환해 주는 것은 맞지만, **HBM 대역폭의 관점에서 결정적인 사실은 이것입니다.**

> **광폭 버스는 인터포저 안에서 끝납니다. 패키지 밖으로 나가지 않습니다.**

프로세서와 HBM 사이의 약 3,900개 신호는 **인터포저 배선층을 통해 옆으로 이어질 뿐**, C4 범프로 내려가지 않습니다. 아래로 내려가는 것은 두 부류뿐입니다.

- **전원과 접지** — 인터포저 자체의 TSV를 통해 위로 공급됩니다
- **프로세서의 외부 I/O** — PCIe, 이더넷, 시스템 메모리 등

이 사실의 무게가 큽니다. [02장](../02_memory_wall/)에서 폭의 벽을 만든 제약 목록을 다시 보면,

| 제약 | 광폭 버스가 인터포저에서 끝나면 |
|---|---|
| 패키지 핀 수 상한 | **해당 없음** — 패키지를 지나지 않는다 |
| PCB 배선 면적·층 수 | **해당 없음** — PCB를 지나지 않는다 |
| 길이 정합 난이도 | 크게 완화 — 거리가 mm 단위다 |
| 전력 | 크게 완화 — 배선이 짧아 비트당 에너지가 낮다 |

**폭의 벽을 이룬 제약들이 통째로 무효가 됩니다.** 인터포저가 하는 일의 본질이 이것입니다 — 피치 변환기가 아니라 **광폭 버스를 가둬 두는 공간**입니다.

### "2.5D"라는 이름의 뜻

용어를 정리하면 이렇습니다.

| 이름 | 구조 |
|---|---|
| **2D** | 칩들을 보드 위에 나란히 놓고 PCB 배선으로 잇는다 |
| **2.5D** | 칩들을 **인터포저 위에** 나란히 놓고 인터포저 배선으로 잇는다 |
| **3D** | 칩을 **위로 쌓고** TSV로 잇는다 |

HBM 시스템은 **둘을 함께** 씁니다.

- HBM 스택 **내부**는 **3D** — die를 쌓고 TSV로 관통 ([03장](../03_stacking_tsv/))
- 스택과 프로세서 **사이**는 **2.5D** — 인터포저 위에 나란히

"2.5"라는 어정쩡한 이름은 **평면(2D)이지만 실리콘을 쓴다(3D의 기술)** 는 중간 성격에서 왔습니다.

## 5. 디테일 — 왜 프로세서 위에 바로 쌓지 않는가

당연한 질문이 하나 남습니다. **3D가 거리를 더 줄이는데, 왜 HBM을 프로세서 위에 직접 쌓지 않을까요?** 그러면 인터포저도 필요 없습니다.

이유가 셋입니다. 첫 번째가 결정적입니다.

### ① 열 — 프로세서가 뜨겁다

프로세서는 시스템에서 **가장 뜨거운 부품**입니다. 그 위에 DRAM을 쌓으면 두 가지가 동시에 나빠집니다.

- **프로세서의 열이 빠져나갈 길이 막힙니다.** 위에 die가 덮여 있으면 방열판까지 가는 경로에 실리콘 여러 장이 끼어듭니다.
- **DRAM이 뜨거워집니다.** 그리고 [01장](../01_dram_operation/)에서 본 대로, DRAM은 뜨거워지면 **refresh를 두 배로** 해야 합니다. 성능이 깎입니다.

```
프로세서 위에 쌓는다
  → DRAM 온도 상승
  → refresh 주기 단축 (tREFI 절반)
  → 뱅크가 멈춰 있는 시간 증가
  → 대역폭 손실
```

거리를 줄이려고 쌓았는데 **대역폭을 잃는** 구조입니다. [07장](../07_thermal/)에서 이 고리를 정량적으로 다룹니다.

### ② 면적이 맞지 않는다

프로세서 die 위에 HBM 스택 여러 개를 올릴 면적이 없습니다. 요즘 가속기는 스택을 **4~8개** 붙이는데, 그만큼을 프로세서 위에 얹을 수 없습니다. 옆에 두면 면적 제약이 훨씬 느슨합니다.

### ③ 수율과 조립

프로세서 die는 크고 비쌉니다. 그 위에 직접 쌓다가 실패하면 **프로세서까지 버립니다.** 인터포저 위에 나란히 놓으면 스택은 별도로 만들어 검사한 뒤 붙일 수 있습니다.

:::tip[그래서 방향은 "가까이, 그러나 위는 아니게"]
HBM의 선택은 **가능한 만큼 가까이 붙이되 프로세서 위는 피한다**입니다. 그 절충이 2.5D이고, 인터포저가 그것을 가능하게 합니다.

다만 이 절충은 고정된 것이 아닙니다. 열 문제를 풀 수 있으면 3D로 갈 이유가 생기고, 실제로 그 방향의 연구가 진행 중입니다.
:::

### 인터포저가 치르는 대가

| 대가 | 내용 |
|---|---|
| **면적** | 프로세서와 스택 여러 개를 모두 담아야 해서 크다. 실리콘 면적은 비싸다 |
| **비용** | 반도체 공정으로 만드는 큰 판이다. 단순한 배선만 있어도 저렴하지 않다 |
| **자체 TSV 필요** | 전원을 아래에서 위로 올려야 하므로 인터포저에도 관통 배선이 필요하다 |
| **크기 상한** | 노광 장비가 한 번에 처리할 수 있는 면적에 상한이 있다. 스택을 몇 개까지 붙일 수 있는지가 여기서 정해진다 |

마지막 항목 때문에 **더 싸고 더 큰 대안**을 찾는 흐름이 있습니다 — 유기 재료 인터포저, 실리콘 조각을 필요한 구간에만 끼우는 브리지 방식, 인터포저 없이 재배선층만 쓰는 방식 등입니다. 어느 쪽이든 **광폭 버스를 짧고 촘촘하게 잇는다**는 목표는 같습니다.

## 6. 흔한 오해

:::caution[넷]
**① "인터포저는 그냥 기판이다"**
일반 PCB가 아니라 **실리콘**이고, **반도체 공정**으로 만듭니다. 그 차이가 배선 밀도를 **50배 이상** 가릅니다.

**② "인터포저는 피치를 바꿔 주는 어댑터다"**
그 역할도 하지만 본질이 아닙니다. 본질은 **광폭 버스를 가둬 두는 공간**입니다 — 3,900개 신호가 패키지·PCB를 지나지 않으므로, 폭의 벽을 이룬 제약들이 통째로 무효가 됩니다.

**③ "HBM은 3D 적층 메모리다"**
스택 **내부**는 3D가 맞지만, 프로세서와의 관계는 **2.5D**입니다. 둘을 함께 씁니다.

**④ "프로세서 위에 쌓으면 더 좋을 것이다"**
거리는 더 줄지만 **열이 막힙니다.** DRAM이 뜨거워지면 refresh가 두 배가 되어 **대역폭을 잃습니다.** 그리고 면적·수율 문제도 따라옵니다.
:::

## 7. 핵심 정리

- 스택 내부는 TSV로 이어졌지만(03장), **스택과 프로세서 사이**가 남는다. 약 **3,900개** 신호를 잇는 문제다.
- 문제의 본질은 **배선 밀도**다 — 일반 PCB 약 **50 µm**, 실리콘 인터포저 약 **1 µm** **[개략]**. **50배 이상** 차이이며, 원인은 **기판 공정 vs 반도체 공정**이다.
- 계산으로 확인 — 3,900개를 한 층에 놓으려면 PCB는 **390 mm**, 인터포저는 **7.8 mm**. 전자는 불가능, 후자는 die보다 짧다.
- 접점 피치는 계단을 오른다 — µbump 약 **40 µm** → C4 약 **150 µm** → BGA 약 **0.5~1 mm** **[개략]**. 한 번에 뛸 수 없어 중간 단계가 필요하다.
- ★ **그러나 핵심은 광폭 버스가 인터포저 안에서 끝난다는 것**이다. 패키지·PCB를 지나지 않으므로 **핀 수 상한과 기판 면적 제약이 통째로 무효**가 된다. 인터포저의 본질은 어댑터가 아니라 **광폭 버스를 가둬 두는 공간**이다.
- **HBM 시스템은 3D와 2.5D를 함께** 쓴다 — 스택 내부는 3D(적층+TSV), 프로세서와는 2.5D(인터포저 위 나란히).
- 프로세서 **위**에 쌓지 않는 이유가 셋 — **열**(DRAM이 뜨거워지면 refresh 두 배 → 대역폭 손실), **면적**(스택 4~8개를 얹을 자리 없음), **수율**(실패 시 프로세서까지 버림).
- 인터포저의 대가 — 면적·비용·자체 TSV·**크기 상한**. 마지막 것이 스택 개수의 상한을 만들고, 그래서 더 싼 대안을 찾는 흐름이 있다.

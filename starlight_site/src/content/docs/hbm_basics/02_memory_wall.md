## 1. Why care? — 연산기는 빨라졌는데 왜 굶는가

[01장](../01_dram_operation/)에서 결론 하나를 얻었습니다 — **DRAM의 지연은 수십 년간 거의 그대로이고, 개선된 것은 대역폭**입니다.

그러면 대역폭은 충분히 개선되었을까요? 숫자를 대 보면 그렇지 않습니다.

연산 유닛이 계산을 하려면 데이터가 있어야 합니다. 그래서 칩의 요구를 이렇게 물을 수 있습니다 — **연산 하나(FLOP)를 하려면 메모리에서 몇 바이트를 가져와야 하는가.**

행렬 곱처럼 데이터를 재사용하는 연산은 비율이 좋습니다. 그런데 **재사용이 적은 연산**은 그렇지 않습니다. 예를 들어 큰 배열 두 개를 더해 세 번째에 쓰는 연산(`c[i] = a[i] + b[i]`)은 덧셈 한 번에 **12바이트**(읽기 8 + 쓰기 4)를 옮겨야 합니다. 연산은 거의 무료이고 **데이터 이동이 전부**입니다.

이런 연산에서 칩의 실효 성능은 **연산 능력이 아니라 대역폭이 정합니다.** 연산 유닛을 두 배로 늘려도 대역폭이 그대로면 성능은 그대로입니다.

그리고 지난 수십 년간 **연산 능력은 대역폭보다 훨씬 빠르게 올랐습니다.** 트랜지스터를 더 넣으면 연산기는 늘리기 쉽지만, 메모리에서 데이터를 끌어오는 능력은 그렇게 늘지 않았습니다. 그 벌어지는 격차를 **Memory Wall**이라고 부릅니다.

이 장은 그 격차를 좁히려는 시도들을 **하나씩 순서대로** 따라갑니다. 그리고 각각이 어디서 막히는지 확인합니다. 마지막 하나가 막히는 지점에서 HBM이 나옵니다.

## 2. 직관 — 대역폭은 두 개의 손잡이로만 조절된다

대역폭의 정의는 놀랄 만큼 단순합니다.

> **대역폭 = 버스 폭 × 전송률**

동시에 나르는 선의 개수와, 선 하나가 초당 나르는 비트 수의 곱입니다. 원리상 손잡이는 **둘뿐**입니다.

그런데 [01장](../01_dram_operation/)에서 본 대로, DRAM 안쪽에는 손잡이가 두 개 더 있습니다 — **프리페치**와 **뱅크 수**입니다. 이 둘은 버스 폭·전송률을 건드리지 않고도 "버스를 쉬지 않게 채우는" 역할을 합니다.

그래서 손잡이가 모두 **네 개**이고, 안쪽부터 바깥쪽 순서로 돌려 볼 수 있습니다.

```d2
direction: down

Q: "대역폭을 올려야 한다" { style.fill: "#e3f2fd"; style.font-color: "#0A0F25" }

INSIDE: "칩 안쪽 손잡이" {
  style.fill: "#f5f5f5"; style.font-color: "#0A0F25"

  P: "① 프리페치를 키운다\n한 번에 더 많이 꺼낸다" { style.fill: "#e8f5e9"; style.font-color: "#0A0F25" }
  B: "② 뱅크를 늘린다\n대기 시간을 겹친다" { style.fill: "#e8f5e9"; style.font-color: "#0A0F25" }
}

OUTSIDE: "칩 바깥쪽 손잡이" {
  style.fill: "#f5f5f5"; style.font-color: "#0A0F25"

  S: "③ 전송률을 올린다\n선 하나를 더 빠르게" { style.fill: "#fff8e1"; style.font-color: "#0A0F25" }
  W: "④ 버스를 넓힌다\n선을 더 많이" { style.fill: "#fff8e1"; style.font-color: "#0A0F25" }
}

WALL: "③과 ④가 부딪히는 벽은 같은 원인에서 온다\n배선의 길이" {
  style.fill: "#ffebee"; style.font-color: "#0A0F25"
}

ESCAPE: "거리를 줄인다\n= 옆에 놓고 위로 쌓는다" { style.fill: "#f3e5f5"; style.font-color: "#0A0F25" }

Q -> INSIDE: "먼저 여기"
INSIDE -> OUTSIDE: "한계에 닿으면"
OUTSIDE -> WALL
WALL -> ESCAPE: "탈출구"
```

이 장의 나머지는 이 순서를 따라갑니다.

## 3. 작은 예 — 같은 대역폭, 두 가지 방법

숫자로 감을 잡아 봅시다. **1 TB/s**를 만들어야 한다고 합시다. 손잡이 ③과 ④를 각각 극단적으로 쓰면 이렇게 됩니다.

**방법 A — 좁고 빠르게**

```
버스 폭  384 비트
전송률   21 Gb/s  (핀 하나당)

대역폭 = 384 × 21 Gb/s ÷ 8 = 1,008 GB/s ≈ 1 TB/s
```

**방법 B — 넓고 느리게**

```
버스 폭  2048 비트
전송률   4 Gb/s  (핀 하나당)

대역폭 = 2048 × 4 Gb/s ÷ 8 = 1,024 GB/s ≈ 1 TB/s
```

대역폭은 같습니다. 그런데 치르는 대가가 전혀 다릅니다.

| | 방법 A (좁고 빠르게) | 방법 B (넓고 느리게) |
|---|---|---|
| 신호선 수 | **384** | **2048** — 5배 이상 |
| 핀 하나의 부담 | 21 Gb/s — 매우 어려움 | 4 Gb/s — 쉬움 |
| 신호 무결성 | 극도로 어려움 | 상대적으로 쉬움 |
| 배선을 놓을 면적 | 적게 필요 | **많이 필요** |
| 비트당 에너지 | 높음 | 낮음 |

여기서 질문이 생깁니다. **방법 B가 신호 무결성도 쉽고 에너지도 낮은데, 왜 다들 A를 해 왔을까요?**

답은 **2048개의 선을 놓을 자리가 없었기 때문**입니다. 그 자리를 만드는 것이 HBM이 한 일이고, 이 장의 나머지가 그 이야기입니다.

:::tip[제품 수준의 비교가 궁금하면]
실제 DDR5·GDDR6·HBM3E의 대역폭을 나란히 놓고 비교한 표와, 그것이 검증 직무에 어떤 의미인지는 [`hbm` 코스 Ch01](../../hbm/01_why_hbm/)에 있습니다. 이 장은 **왜 그런 형태가 되었는지의 물리**에 집중합니다.
:::

## 4. 일반화 — 네 손잡이를 하나씩 돌려 본다

### 손잡이 ① 프리페치를 키운다

[01장](../01_dram_operation/)에서 본 대로, 내부에서 한 번에 넓게 꺼내 바깥으로 빠르게 나눠 보내는 방식입니다. 버스트 길이를 늘리면 대역폭이 올라갑니다.

**한계 — 낭비가 생긴다.** 버스트가 길어지면 **필요 없는 데이터까지 가져옵니다.** 4바이트만 필요한데 버스트가 64바이트면 60바이트는 버려집니다. 이것을 **오버페치**라고 하고, 실효 대역폭을 깎습니다.

그래서 버스트 길이는 무한정 늘릴 수 없습니다. HBM4가 `BL = 8`에 머무는 것도 이 균형점 때문입니다.

### 손잡이 ② 뱅크를 늘린다

대기 시간을 겹쳐 버스를 쉬지 않게 만드는 방식입니다.

**한계 — 결국 버스가 병목이 된다.** 뱅크를 아무리 늘려도 **버스가 이미 꽉 차 있으면** 더 이상 나아지지 않습니다. 뱅크 늘리기는 "버스를 100% 쓰게" 만들 뿐, 버스 자체의 용량을 늘리지 못합니다.

그리고 뱅크마다 sense amplifier 배열이 따로 필요하므로 **면적**을 먹습니다.

**①과 ②는 칩 안에서 할 수 있는 일이고, 이미 거의 소진되었습니다.** 남은 것은 버스 자체입니다.

### 손잡이 ③ 전송률을 올린다 — 첫 번째 벽

핀 하나가 초당 나르는 비트를 늘립니다. 클럭을 올리는 것에 해당합니다.

**한계 — 신호가 배선을 지나며 뭉개진다.**

디지털 신호는 "0과 1이 딱딱 떨어진다"고 생각하기 쉽지만, 실제로 배선을 지나는 것은 **전압 파형**입니다. 그 파형이 긴 배선을 지나면 세 가지 일이 생깁니다.

| 현상 | 무슨 일인가 |
|---|---|
| **감쇠** | 배선의 저항과 유전 손실로 신호가 작아진다. 주파수가 높을수록 심하다 |
| **번짐 (ISI)** | 파형이 시간축으로 퍼져서 **앞 비트가 뒤 비트에 겹친다** |
| **반사·간섭** | 임피던스가 어긋난 지점에서 신호가 되돌아오고, 옆 선과 간섭한다 |

전송률을 올리면 비트 하나에 주어진 시간이 짧아지는데, 번짐의 정도는 배선이 정하므로 **비트 시간이 번짐보다 짧아지는 순간 판독이 불가능**해집니다.

이걸 이기는 방법은 있습니다 — 등화(equalization), 더 강한 드라이버, 더 정교한 트레이닝. 그런데 **그 전부가 에너지를 씁니다.** 그래서 전송률을 올릴수록 **비트당 에너지가 올라갑니다.**

그리고 결정적인 사실 하나 — **이 어려움은 배선 길이에 비례합니다.** 같은 20 Gb/s를 보내도, 5 cm를 가는 것과 5 mm를 가는 것은 난이도가 전혀 다릅니다.

### 손잡이 ④ 버스를 넓힌다 — 두 번째 벽

선을 더 많이 놓습니다. 방법 B가 이쪽입니다.

**한계 — 놓을 자리가 없다.**

| 제약 | 내용 |
|---|---|
| **패키지 핀 수** | 칩 밖으로 뺄 수 있는 핀 수에 물리적 상한이 있다 |
| **PCB 배선 면적** | 고속 신호선은 간격을 띄워야 하고 그라운드도 같이 깔아야 한다. 선이 2048개면 기판 면적과 층 수가 폭발한다 |
| **길이 정합** | 병렬 버스는 모든 선의 지연이 맞아야 한다. 선이 많아질수록 맞추기 어렵다 |
| **전력** | 선이 많아지면 드라이버도 그만큼 많아진다 |

그리고 이 제약들도 **배선 길이와 함께 나빠집니다.** 짧으면 간격을 좁혀도 간섭이 덜하고, 길이 정합도 쉽습니다.

### 두 벽의 공통 분모

여기서 이 장의 핵심이 나옵니다.

> **③의 벽(신호가 뭉개진다)과 ④의 벽(자리가 없다)은 서로 다른 문제처럼 보이지만, 둘 다 배선이 길기 때문에 생깁니다.**

그렇다면 **거리를 줄이면 두 벽이 동시에 물러납니다.**

- 배선이 짧아지면 → 신호가 덜 뭉개지고, 비트당 에너지가 내려간다 → **전송률에 여유가 생긴다**
- 배선이 짧아지면 → 미세한 간격으로 촘촘히 놓을 수 있다 → **폭에 여유가 생긴다**

HBM의 정체가 이것입니다. **HBM은 빠른 메모리가 아니라 가까운 메모리이고, 가깝기 때문에 넓을 수 있는 메모리입니다.**

## 5. 디테일 — 그래서 얼마나 가까이 붙여야 하나

"거리를 줄인다"는 말을 구체화해 봅시다.

| 방식 | 신호가 지나는 거리 | 배선 폭·간격 |
|---|---|---|
| 메모리 모듈을 소켓에 꽂는다 (DDR) | **수 cm** — PCB 위 | 수십 µm |
| 메모리 칩을 보드에 직접 붙인다 (GDDR) | **1~2 cm** | 수십 µm |
| 메모리를 프로세서 **옆에** 놓고 실리콘으로 잇는다 | **수 mm** | **수 µm** |
| 메모리를 프로세서 **위에** 쌓는다 | **수십 µm** | **수 µm 이하** |

아래로 갈수록 거리가 **자릿수 단위로** 줄어듭니다. 그리고 배선 폭도 함께 줄어듭니다 — 이것이 폭을 넓힐 수 있는 이유입니다. 배선이 가늘어지면 같은 면적에 훨씬 많은 선이 들어갑니다.

HBM은 아래 두 가지를 **함께** 씁니다.

- **위로 쌓는다** — DRAM die를 여러 장 적층하고, die를 관통하는 배선으로 잇는다 → [03장 TSV](../03_stacking_tsv/)
- **옆에 놓는다** — 그 스택을 프로세서와 나란히 두고, 실리콘 판 위의 미세 배선으로 잇는다 → [04장 인터포저](../04_interposer/)

:::caution[여기서 흔한 오해를 하나 교정합니다]
**"쌓으면 대역폭이 올라간다"** — 이 문장은 그대로는 틀렸습니다.

층을 쌓는 것 자체가 직접 늘리는 것은 **용량**입니다. 4층을 8층으로 바꾸면 용량이 두 배가 되지만, 대역폭은 그것만으로 두 배가 되지 않습니다. 실제로 HBM 규격은 **스택 높이와 무관하게 채널 수를 고정**합니다 — HBM4는 4층이든 16층이든 32채널입니다.

쌓기가 대역폭에 기여하는 방식은 **간접적**입니다.

```
쌓는다  →  프로세서와의 거리가 짧아진다
        →  배선을 가늘고 촘촘하게 놓을 수 있다
        →  버스를 아주 넓게 만들 수 있다   ← 여기서 대역폭이 나온다
```

즉 **쌓기는 폭을 얻기 위한 수단**입니다. 대역폭은 여전히 폭에서 나옵니다.
:::

## 6. 흔한 오해

:::caution[넷]
**① "HBM은 빠른 메모리다"**
핀 하나당 전송률은 **GDDR보다 낮습니다.** HBM4의 규격 등급이 4.8~8.0 Gb/s인데 GDDR6는 20 Gb/s 안팎입니다. HBM은 빠른 게 아니라 **넓습니다.**

**② "쌓으면 대역폭이 올라간다"**
층 쌓기가 직접 늘리는 것은 **용량**입니다. 대역폭은 폭에서 나오고, 쌓기는 그 폭을 가능하게 하는 **수단**입니다. HBM4의 채널 수는 스택 높이와 무관하게 32개로 고정입니다.

**③ "대역폭이 크면 지연도 짧다"**
별개입니다. HBM의 지연은 DDR과 비슷하거나 오히려 조금 깁니다 — 신호가 base die를 거쳐 TSV를 타고 올라가야 하니까요. HBM이 개선하는 것은 **처리량**입니다.

**④ "선을 많이 놓는 게 뭐가 어렵나"**
고속 신호선은 하나씩 놓는 게 아닙니다. 간격을 띄우고 그라운드를 깔고 길이를 맞춰야 합니다. 2048개를 일반 PCB로 빼려면 기판 층 수와 면적이 감당 불가능한 수준이 됩니다 — [04장](../04_interposer/)에서 숫자로 봅니다.
:::

## 7. 핵심 정리

- **Memory Wall**은 연산 능력이 대역폭보다 빠르게 올라 생긴 격차다. 재사용이 적은 연산에서 성능은 **대역폭이 정한다.**
- **대역폭 = 버스 폭 × 전송률.** 손잡이는 원리상 둘뿐이고, DRAM 안쪽에 프리페치·뱅크 두 개가 더 있다.
- **① 프리페치** — 늘리면 **오버페치**로 낭비가 생긴다. **② 뱅크** — 늘려도 버스가 꽉 차면 무의미하다. 둘 다 거의 소진되었다.
- **③ 전송률의 벽** — 신호가 배선에서 **감쇠·번짐(ISI)·반사**로 뭉개진다. 이기려면 에너지를 쓴다.
- **④ 폭의 벽** — 패키지 핀 수, PCB 면적과 층 수, 길이 정합, 전력.
- ★ **③과 ④의 벽은 같은 원인에서 온다 — 배선이 길기 때문이다.** 거리를 줄이면 두 벽이 동시에 물러난다.
- 그래서 HBM은 **가까운 메모리**이고, 가깝기 때문에 **넓을 수 있는** 메모리다. 대역폭은 여전히 **폭**에서 나온다.
- 거리를 줄이는 두 수단 — **위로 쌓기**(03장)와 **옆에 놓기**(04장). 그 대가로 열 문제가 생긴다(07장).

### 다음 장

"거리를 줄이면 된다"까지 왔습니다. 그런데 **die를 쌓으면 위층과 아래층은 무엇으로 연결하는가?** 옆으로 선을 빼서 돌아가면 거리를 줄인 의미가 없습니다.

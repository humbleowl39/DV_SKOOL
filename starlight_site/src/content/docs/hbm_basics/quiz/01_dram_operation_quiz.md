## Q1. (Remember)

DRAM 셀 하나의 구성으로 옳은 것은?

- [ ] A. 트랜지스터 6개
- [ ] B. 트랜지스터 1개 + 커패시터 1개
- [ ] C. 커패시터 2개
- [ ] D. 트랜지스터 2개 + 저항 1개

<details>
<summary>정답 / 해설</summary>

**B**. 이것을 **1T1C** 라고 부릅니다. A(트랜지스터 6개)는 **SRAM** 셀의 구성입니다.

**왜 중요한가**: 이 단순함이 DRAM 의 밀도를 만들고, 동시에 커패시터의 세 가지 성질 — 전하가 적다 · 읽으면 빠진다 · 가만히 둬도 샌다 — 이 DRAM 의 모든 복잡함을 만듭니다.

</details>

## Q2. (Understand) ★

"읽기가 파괴적(destructive)"이라는 말의 뜻과 그 귀결을 가장 잘 설명한 것은?

- [ ] A. 읽으면 셀이 물리적으로 손상되므로 수명이 줄어든다
- [ ] B. 읽으면 전하가 빠져나가 원본이 소실되므로, 판독 직후 같은 값을 다시 써 넣는 복원이 뒤따른다
- [ ] C. 읽으면 같은 행의 다른 셀 값이 바뀐다
- [ ] D. 읽기 중에는 쓰기를 할 수 없다

<details>
<summary>정답 / 해설</summary>

**B**. 셀의 전하가 bit line 으로 흘러나오면서 원본이 사라지고, sense amplifier 가 판정한 값을 셀에 되써 넣습니다.

**왜 중요한가**: 이 복원이 자동으로 뒤따르기 때문에 `ACT` 부터 `PRE` 까지 최소 시간(**`tRAS`**)이 강제됩니다. 복원이 덜 끝난 채 행을 닫으면 셀에 약한 전하만 남아 다음 refresh 전에 데이터를 잃습니다.

A 는 틀립니다 — 물리적 손상이 아니라 전하의 이동입니다.

</details>

## Q3. (Understand)

`ACT` 커맨드를 발행했을 때 실제로 일어나는 일은?

- [ ] A. 지정한 셀 하나가 열린다
- [ ] B. 지정한 행의 모든 셀이 동시에 열려 전하를 내놓고, sense amplifier 배열이 그 값을 붙든다
- [ ] C. 지정한 열의 모든 셀이 열린다
- [ ] D. 뱅크 전체가 초기화된다

<details>
<summary>정답 / 해설</summary>

**B**. word line 하나를 켜면 **그 행 전체**가 열립니다. 하나만 읽고 싶어도 행 전체가 나옵니다.

그 행을 받아 붙들고 있는 sense amplifier 들의 배열이 **Row Buffer** 이며, 열 주소는 그 안에서 어느 칸을 내보낼지만 고릅니다.

**왜 중요한가**: 이 구조가 **행 히트**를 설명합니다 — 같은 행의 다른 열은 이미 꺼내 놓은 것 중에서 고르는 것이라 `ACT` 도 `tRCD` 도 필요 없습니다.

</details>

## Q4. (Apply)

행 히트 · 행 미스 · 행 충돌 세 경우에 각각 필요한 커맨드 순서를 옳게 짝지은 것은?

- [ ] A. 히트: `RD` / 미스: `ACT`→`RD` / 충돌: `PRE`→`ACT`→`RD`
- [ ] B. 히트: `ACT`→`RD` / 미스: `RD` / 충돌: `PRE`→`RD`
- [ ] C. 세 경우 모두 `ACT`→`RD`
- [ ] D. 히트: `RD` / 미스: `PRE`→`RD` / 충돌: `ACT`→`RD`

<details>
<summary>정답 / 해설</summary>

**A**.

| 상황 | 필요한 것 | 대략 |
|---|---|---|
| **행 히트** — 원하는 행이 이미 열려 있다 | `RD` + `CL` | ~15 ns |
| **행 미스** — 뱅크가 닫혀 있다 | `ACT` + `tRCD` + `RD` + `CL` | ~30 ns |
| **행 충돌** — 다른 행이 열려 있다 | `PRE` + `tRP` + `ACT` + `tRCD` + `RD` + `CL` | ~45 ns |

**왜 중요한가**: 같은 데이터를 읽어도 **접근 순서에 따라 3배 차이**가 납니다. 그리고 세 결말 중 무엇이 되는지는 주소가 어떤 순서로 오느냐에 달려 있습니다 — 메모리 성능이 예측하기 어려운 근본 이유입니다.

</details>

## Q5. (Analyze) ★

뱅크를 16개에서 64개로 늘리면 무엇이 달라지는가?

- [ ] A. 지연과 대역폭이 모두 늘어난다
- [ ] B. 지연은 줄고 대역폭은 그대로다
- [ ] C. 지연은 그대로이고 대역폭이 늘어난다
- [ ] D. 둘 다 변하지 않는다

<details>
<summary>정답 / 해설</summary>

**C**.

한 뱅크에서 `ACT` → `RD` → `PRE` 를 하는 동안 그 뱅크는 다른 요청을 받을 수 없습니다. 뱅크가 여럿이면 그 **대기 시간이 서로 겹칩니다**(뱅크 인터리빙).

| | 뜻 | 뱅크를 늘리면 |
|---|---|---|
| **지연** | 요청 하나가 답을 받기까지 | **변하지 않는다** |
| **대역폭** | 단위 시간당 나르는 양 | **올라간다** |

**왜 중요한가**: 이것이 **DRAM 지연이 수십 년간 개선되지 않은** 이유의 절반입니다. 커패시터를 읽고 증폭하는 물리적 시간은 뱅크를 늘려도 줄지 않습니다. 개선된 것은 대역폭이고, 그 방법이 더 많은 뱅크와 더 넓은 버스였습니다. 이 결론이 [02장](../../02_memory_wall/)의 출발점입니다.

</details>

## Q6. (Evaluate)

"refresh 는 백그라운드에서 알아서 도니까 성능과 무관하다"는 주장을 평가하라. 그리고 온도가 개입하는 경로를 설명하라.

<details>
<summary>정답 / 해설</summary>

**틀렸습니다. refresh 는 성능을 직접 깎습니다.**

`tRFC` 동안 해당 뱅크는 **아무 일도 하지 못합니다.** `tREFI`(~3.9 µs)마다 `tRFC`(~100~350 ns)를 쓰므로 전체 시간의 몇 퍼센트를 뺏깁니다. 용량이 커질수록 돌아야 할 행이 늘어 `tRFC` 가 길어집니다.

**온도가 개입하는 경로**:

```
온도 상승 → 커패시터 전하 누설이 빨라진다
         → tREFI 를 절반으로 줄여야 한다 (통상 85 °C 초과 시)
         → REF 발행 빈도 2배
         → 뱅크가 멈추는 시간 2배
         → 실효 대역폭 감소
```

**왜 중요한가**: **뜨거워지면 느려집니다.** 이 고리가 HBM 처럼 die 를 쌓아 열이 갇히는 구조에서 특히 중요해지며, [07장](../../07_thermal/)에서 되먹임까지 포함해 마무리합니다.

</details>

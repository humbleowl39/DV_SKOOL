## Q1. (Remember)

Core die 와 base die 의 차이를 옳게 설명한 것은?

- [ ] A. core die 는 아래, base die 는 위에 있다
- [ ] B. core die 는 셀 어레이를 담고, base die 는 데이터를 담지 않고 인터페이스·관리를 담당한다
- [ ] C. 둘 다 셀을 담지만 용량이 다르다
- [ ] D. base die 가 여러 장, core die 가 한 장이다

<details>
<summary>정답 / 해설</summary>

**B**. base die 는 **스택 최하단 한 장**이며 **호스트가 유일하게 마주보는 층**입니다. core die 는 여러 장(4·8·12·16)이고 호스트를 직접 보지 않습니다.

A 는 위아래가 반대입니다 — base die 가 **최하단**입니다.

</details>

## Q2. (Understand) ★

8-high 구성에서 채널 하나는 core die 몇 장에 걸쳐 있는가? 그리고 그것을 구분하는 주소 필드는?

- [ ] A. 1장 / 채널 주소
- [ ] B. 2장 / SID
- [ ] C. 8장 / 뱅크 주소
- [ ] D. 4장 / PC 비트

<details>
<summary>정답 / 해설</summary>

**B**. **2장**이며 **SID(Stack ID)** 로 구분합니다.

HBM4 는 채널을 **32개로 고정**하고, 32채널을 만들려면 core die 가 **최소 4장** 필요합니다. 8-high 면 die 가 8장이므로 채널 하나가 **die 2장**에 걸칩니다.

**왜 중요한가**: ★ **채널은 논리 단위, die 는 물리 단위이며 둘은 일치하지 않습니다.** "die 하나 = 채널 하나"라는 직관이 여기서 깨집니다.

</details>

## Q3. (Apply)

스택 높이가 12-high 일 때 SID 유효값이 4개가 아니라 **3개**인 이유를 설명하고, 그때 채널당 뱅크 수를 구하라.

<details>
<summary>정답 / 해설</summary>

**SID 유효값이 3개인 이유**: `SID[1:0]` 은 2비트라 네 값을 표현할 수 있지만, 규격이 **`SID[1:0] = 11` 을 무효**로 둡니다. 12-high 는 die 가 12장(=4×3)이므로 구분할 묶음이 3개뿐이고, 남는 조합 하나를 무효로 만든 것입니다.

**채널당 뱅크 수**: die 4장 묶음 하나가 채널당 16뱅크를 제공하므로

```
16 × 3 = 48 뱅크
```

**전체 표**:

| 스택 높이 | SID 유효값 | 채널당 뱅크 |
|---|---|---|
| 4-high | 1 | 16 |
| 8-high | 2 | 32 |
| **12-high** | **3** | **48** |
| 16-high | 4 | 64 |

규격이 정의한 "채널당 16 / 32 / 48 / 64 뱅크"와 정확히 맞습니다 — **외우는 값이 아니라 유도되는 값**입니다.

</details>

## Q4. (Analyze) ★

스택을 4-high 에서 16-high 로 높이면 다음 중 무엇이 늘어나고 무엇이 그대로인가?
① 용량 ② 채널당 뱅크 수 ③ 채널 수 ④ 버스 폭 ⑤ 대역폭

<details>
<summary>정답 / 해설</summary>

| 항목 | 결과 |
|---|---|
| ① 용량 | **늘어난다** (12 → 48 GB, 24 Gb die 기준) |
| ② 채널당 뱅크 | **늘어난다** (16 → 64) |
| ③ 채널 수 | **그대로** (32) |
| ④ 버스 폭 | **그대로** (2,048비트) |
| ⑤ 대역폭 | **그대로** |

**왜 중요한가**: ★ **스택 높이는 대역폭을 바꾸지 않습니다.** 폭이 고정이므로 대역폭을 바꾸는 것은 **전송률**뿐입니다.

[02장](../../02_memory_wall/)에서 *"쌓기는 폭을 얻기 위한 수단"* 이라고 했습니다. 이 표가 그 문장의 정확한 의미입니다 — 쌓을 수 있는 **구조**(짧은 거리·미세 배선)가 넓은 버스를 가능하게 했고, 일단 그 구조를 얻은 뒤에는 더 쌓아도 **용량만** 늡니다.

</details>

## Q5. (Evaluate)

채널 하나가 die 4장에 걸치면 base die 에서 각 die 까지의 거리가 다르다. 규격은 "한 채널 내 모든 접근은 동일 레이턴시"를 요구한다. 이 요구가 무엇을 강제하며, 그 대가로 무엇을 얻는가?

<details>
<summary>정답 / 해설</summary>

**강제하는 것**: 벤더가 **짧은 경로에 의도적으로 지연을 넣어 균등화**해야 합니다. 결과적으로 **레이턴시가 가장 먼 경로에 맞춰 고정**됩니다.

**대가**: 성능입니다 — 가까운 die 도 먼 die 만큼 기다립니다.

**얻는 것**: **메모리 컨트롤러가 die 위치를 알 필요가 없습니다.**

만약 SID 마다 지연이 다르면 컨트롤러는 어느 주소가 어느 die 에 있는지 알고 스케줄링해야 하고, **스택의 물리적 구성에 종속**됩니다. 레이턴시를 균등화하면 컨트롤러는 채널을 하나의 균일한 저장 공간으로 다루면 됩니다.

**왜 중요한가**: 규격이 복잡함을 **장치 쪽으로 밀어 넣고 호스트를 단순하게** 유지한 설계 판단입니다. HBM 규격에서 반복해서 나타나는 패턴입니다.

</details>

## Q6. (Understand)

"base die 는 HBM 의 필수 구성이다"라는 주장을 규격 근거로 평가하라.

<details>
<summary>정답 / 해설</summary>

**규격은 base die 를 요구하지 않습니다.**

> DRAM 벤더는 스택 최하단에 신호 재분배 등의 기능을 제공하는 **선택적 인터페이스 다이를 요구하도록 선택할 수 있다.** **본 표준은 그러한 해법을 명시적으로 요구하지도, 금지하지도 않는다.** — HBM4 규격 §3 (요약)

규격이 정의하는 것은 **호스트가 보는 인터페이스와 동작**입니다. 그것을 어떤 물리 구조로 만족시킬지는 벤더의 몫입니다. 실제 제품에는 거의 항상 base die 가 있지만, **규격이 강제한 것은 아닙니다.**

**왜 중요한가**: 규격이 "요구하지도 금지하지도 않는다"고 쓴 자리가 곧 **벤더가 자유롭게 쓸 수 있는 공간**입니다. 그래서 HBM4 에서 base die 가 로직 공정으로 이동하며 남는 자리에 메모리 컨트롤러·가속 로직을 넣는 **Custom HBM** 이 성립합니다.

</details>

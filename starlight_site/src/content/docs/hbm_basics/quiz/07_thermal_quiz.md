## Q1. (Understand) ★

스택 안에서 가장 뜨거운 곳은 어디이며 그 이유는?

- [ ] A. 최상단 core die — 방열판과 마찰하기 때문
- [ ] B. base die — 전력을 가장 많이 쓰면서 방열판에서 가장 멀기 때문
- [ ] C. 중간 core die — 양쪽에서 열이 오기 때문
- [ ] D. 모든 die 가 균등하다

<details>
<summary>정답 / 해설</summary>

**B**. 두 조건이 **최악으로 겹칩니다.**

- **전력 최대** — base die 는 수천 개의 I/O 드라이버와 인터페이스·관리 로직을 담습니다. core die 의 셀 어레이는 접근할 때만 전력을 씁니다.
- **방열판에서 최대 거리** — 방열판은 스택 **위쪽**에 있고 base die 는 **최하단**입니다.

그래서 base die 의 열은 위에 쌓인 core die 를 **전부 통과해서** 방열판까지 가야 합니다.

**왜 중요한가**: HBM4 에서 base die 가 로직 공정으로 이동해 **더 많은 로직을 담게 되면** 이쪽 전력이 더 커집니다 — 가장 나쁜 열 위치에 발열이 늘어납니다.

</details>

## Q2. (Understand)

적층 스택에서 열 경로의 주된 병목은?

- [ ] A. 실리콘 자체의 열전도
- [ ] B. die 사이 µbump 층 — 층마다 열 저항이 붙고, 층 수와 함께 늘어난다
- [ ] C. TSV
- [ ] D. 방열판

<details>
<summary>정답 / 해설</summary>

**B**. 실리콘 자체는 열을 꽤 잘 전달합니다. 문제는 **실리콘이 아닌 것들**입니다 — µbump 와 그 사이를 채우는 접착 수지의 열전도는 실리콘보다 훨씬 나쁩니다.

```
16-high 스택에서 base die 의 열이 방열판까지 가려면
  → core die 16장을 통과
  → 그 사이 접합면 16겹을 통과   ← 병목
```

**왜 중요한가**: 층 수가 늘면 통과할 실리콘도 늘지만 **통과할 접합면도 같이** 늡니다. 그래서 스택 높이가 열 문제를 직접 악화시키고, [03장](../../03_stacking_tsv/)에서 본 **하이브리드 본딩**(µbump 를 없앤다)이 더 높은 적층을 가능하게 합니다.

C 는 오답이지만 반대로 TSV 는 구리이므로 **열을 돕습니다.**

</details>

## Q3. (Analyze) ★

박막화(die 를 50 µm 로 갈기)가 열에 미치는 영향을 두 방향으로 나누어 설명하라.

<details>
<summary>정답 / 해설</summary>

**박막화는 양날입니다.**

| 방향 | 영향 |
|---|---|
| **좋은 쪽** | 위아래로 통과할 두께가 얇아지므로 **수직 방향 열 저항이 줄어든다** |
| **나쁜 쪽** | 옆으로 퍼뜨릴 **단면이 줄어든다** |

**두 번째가 중요합니다.** 두꺼운 실리콘은 국소적으로 뜨거운 지점(hot spot)의 열을 **옆으로 퍼뜨려 평준화**합니다. 얇아지면 그 능력이 떨어져 **hot spot 이 국소적으로 더 뜨거워집니다.**

**왜 중요한가**: [03장](../../03_stacking_tsv/)에서 박막화는 **TSV 종횡비 때문에 강제된 것**이었습니다. 즉 *"쌓으려면 얇게"* 라는 요구가 *"얇으면 열이 문제"* 로 이어지는 고리이며, 이 고리는 선택이 아니라 구조적 귀결입니다.

**보완 수단**: TSV 는 구리이므로 열을 위로 나릅니다. 신호를 나르지 않는 **열 전용 TSV** 를 일부러 배치하기도 합니다 — TSV 는 열 문제를 만들기도(박막화 강제) 풀기도(수직 통로) 합니다.

</details>

## Q4. (Analyze) ★

온도가 대역폭을 깎는 고리를 순서대로 쓰고, 그 고리에 되먹임이 있는지 판단하라.

<details>
<summary>정답 / 해설</summary>

**고리**:

```
스택 온도 상승
  → 커패시터 전하가 빨리 샌다
  → tREFI 를 절반으로 (통상 85 °C 초과 시)
  → REF 커맨드 발행 빈도 2배
  → tRFC 동안 뱅크가 멈추는 시간 2배
  → 실효 대역폭 감소
```

**되먹임이 있습니다**:

```
refresh 빈도 2배
  → refresh 는 ACT 를 반복하는 동작이므로 전력을 쓴다
  → 전력 증가 → 온도 상승      ← 출발점으로 돌아온다
```

**양의 되먹임 고리**입니다.

**폭주하지 않는 이유**: 되먹임의 이득이 1보다 작습니다 — refresh 증가로 늘어나는 전력은 전체의 일부이고 냉각 설계가 흡수합니다.

**그러나 여유가 줄면 위험합니다** — 냉각이 부족하거나, 옆의 프로세서가 최대 부하로 돌거나, 스택이 높아 열 경로가 나쁘면 이득이 커집니다. 그래서 **온도 감시와 부하 조절이 필수**입니다.

</details>

## Q5. (Evaluate)

규격이 온도 감시를 **호스트의 의무**로 규정한 것이 왜 특이하며, `CATTRIP` 이 기능 리셋으로 지워지지 않는 이유는?

<details>
<summary>정답 / 해설</summary>

**특이한 점**: 규격은 보통 **장치**가 만족해야 할 것을 규정합니다. 그런데 §7.3 은 **호스트**에게 요구합니다 — *"호스트는 `TEMPERATURE` 와 `CHANNEL_TEMPERATURE` 를 통해 동작 온도를 감시해야 한다"*, *"`CATTRIP` 출력을 감시해야 한다"*. "해야 한다"가 두 번 쓰였습니다.

그리고 그 감시 경로가 **IEEE 1500 테스트 포트**입니다 — 이름은 "테스트"이지만 **정상 동작 내내 필요**합니다.

**`CATTRIP` 이 리셋으로 지워지지 않는 이유**: 파국 온도는 **영구 손상**과 직결됩니다. 손상이 일어났을 가능성이 있다면 그 사실이 **리셋으로 사라져서는 안 됩니다.**

```
파국 온도 초과 → CATTRIP 어서트
  → 리셋을 걸어도 남는다  → 전원을 끊어야 지워진다
```

호스트가 리셋 후 `CATTRIP` 을 읽고 "리셋했으니 깨끗하다"고 가정하면 **과열 이력을 놓칩니다.** 반대로 이 성질 덕분에 리셋을 거쳐도 사건을 추적할 수 있습니다.

</details>

## Q6. (Evaluate)

[05장](../../05_stack_anatomy/)에서 "스택을 높이면 용량만 늘고 대역폭은 그대로"라고 했다. 그렇다면 용량이 필요한 만큼 계속 쌓으면 되는가?

<details>
<summary>정답 / 해설</summary>

**열이 그것을 막습니다. 스택 높이의 실질적 상한은 용량 수요가 아니라 열이 정합니다.**

| 스택을 높이면 | 열 관점 |
|---|---|
| 통과할 접합면이 늘어난다 | 열 저항 ↑ |
| base die 가 방열판에서 더 멀어진다 | 최고 온도 ↑ |
| die 수가 늘어 총 전력이 는다 | 발열량 ↑ |

**세 가지가 모두 나쁜 방향입니다.**

**그래서 하이브리드 본딩이 중요합니다** — µbump 를 없애 접합면의 열 저항을 줄이면 **같은 냉각 조건에서 더 높이 쌓을 수 있습니다.**

**왜 중요한가**: 이 코스의 마지막 문장이 여기에 있습니다 — **모든 이득에 대가가 있고, 그 대가가 다시 성능으로 돌아옵니다.** 쌓으려면 얇게 갈아야 하고, 얇으면 열이 갇히고, 열이 갇히면 refresh 가 두 배가 되어 대역폭을 잃습니다.

</details>

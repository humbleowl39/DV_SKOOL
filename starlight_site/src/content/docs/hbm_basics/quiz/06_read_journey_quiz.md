## Q1. (Remember)

읽기 여정의 다섯 구간을 순서대로 배열한 것은?

- [ ] A. 인터포저 → 주소 쪼개기 → TSV → base die → core die
- [ ] B. 주소 쪼개기 → 인터포저 → base die → TSV → core die
- [ ] C. 주소 쪼개기 → base die → 인터포저 → core die → TSV
- [ ] D. base die → 인터포저 → 주소 쪼개기 → TSV → core die

<details>
<summary>정답 / 해설</summary>

**B**. ① 호스트가 물리 주소를 필드로 쪼갠다 → ② 인터포저를 건넌다 → ③ base die 가 목적지를 정한다 → ④ TSV 로 층을 오른다 → ⑤ core die 에서 행을 열고 열을 고른다.

**가는 길과 오는 길이 같은 구간을 씁니다** — 실어 보내는 것만 다릅니다(커맨드/주소 vs 데이터).

</details>

## Q2. (Understand)

물리 주소가 쪼개지는 필드 중 **장치로 전송되지 않는** 것은?

- [ ] A. 채널 번호
- [ ] B. SID
- [ ] C. 버스트 안의 위치를 고르는 하위 비트
- [ ] D. 행 주소

<details>
<summary>정답 / 해설</summary>

**C**. 한 번의 읽기가 32바이트를 통째로 돌려주므로, 그 안에서 어느 바이트를 쓸지는 **호스트가 알아서** 합니다. 장치는 버스트 내 위치를 구분하지 않습니다.

덧붙여, **`{SID, BA}` 가 실제 뱅크 인덱스**입니다 — SID 는 별도 층 선택 신호가 아니라 뱅크 주소의 확장 비트입니다([05장](../../05_stack_anatomy/)).

</details>

## Q3. (Apply)

HBM4 에서 `RD` 한 번이 PC 당 256비트를 꺼낸다. PC 당 DQ 가 32개일 때 버스트 길이는 몇이고, 전송률 6.4 Gb/s 에서 버스트 전체에 걸리는 시간은?

<details>
<summary>정답 / 해설</summary>

```
256 비트 ÷ 32 핀 = 핀당 8 비트  →  BL8
1 UI = 1 / 6.4 Gb/s ≈ 156 ps
버스트 전체 = 8 × 156 ps ≈ 1.25 ns
```

그리고 256비트 = **32바이트**이므로, 한 번의 읽기가 정확히 32바이트를 돌려줍니다.

**왜 중요한가**: 01~05장의 값들이 여기서 하나로 맞물립니다 — 프리페치 256비트([01장](../../01_dram_operation/)), PC 당 32 DQ([05장](../../05_stack_anatomy/)), BL8, 그리고 규격 등급 6.4 Gb/s.

</details>

## Q4. (Analyze) ★

인터포저 5 mm 를 지나는 전파 지연이 약 0.03 ns 이고 전체 읽기 지연이 수십 ns 라면, "거리를 줄여서 지연이 줄었다"는 주장은 옳은가? 그렇다면 거리를 줄여 얻은 것은 무엇인가?

<details>
<summary>정답 / 해설</summary>

**옳지 않습니다.**

```
인터포저 5 mm   → 약 0.03 ns
옛 방식 PCB 5 cm → 약 0.3 ns
전체 읽기 지연   → 수십 ns
```

거리를 **100배 줄여도 전체 지연은 1 % 도 줄지 않습니다.**

**거리를 줄여 얻은 것**:

| 얻은 것 | 얻지 못한 것 |
|---|---|
| **비트당 에너지가 낮아진다** | ❌ 지연 |
| **신호가 덜 뭉개진다** → 낮은 전송률로도 안정 | |
| **배선을 가늘고 촘촘하게** → 폭을 넓힐 수 있다 | |

**왜 중요한가**: ★ [02장](../../02_memory_wall/)에서 *"거리를 줄이면 두 벽이 물러난다"* 고 했는데, 그 벽은 **지연의 벽이 아니었습니다.** 얻은 것은 **에너지와 폭**이고, 그 폭이 대역폭을 줍니다.

그래서 HBM 의 지연은 DDR 과 비슷하거나 **오히려 조금 깁니다** — base die 를 한 번 더 거치기 때문입니다.

</details>

## Q5. (Evaluate) ★

"메모리 지연은 신호가 멀리 이동하기 때문이다"라는 설명을 평가하고, 지연의 정체를 정확히 진술하라.

<details>
<summary>정답 / 해설</summary>

**틀렸습니다.**

> **DRAM 지연의 대부분은 "거리"가 아니라 "동작"이다.**

`tRCD` 동안 신호는 **어디로도 이동하지 않습니다.** word line 이 켜지고, 셀의 미세한 전하가 bit line 에 퍼지고, sense amplifier 가 그 차이를 판정 가능한 크기로 키우는 **물리적 동작에 걸리는 시간**입니다.

**왜 중요한가**: 이것이 **DRAM 지연이 수십 년간 개선되지 않은 이유**입니다. 물리적 동작 시간은 배선을 짧게 해서 줄일 수 없습니다.

[01장](../../01_dram_operation/)에서 *"메모리는 값을 그냥 꺼내지 않는다"* 고 했습니다. 그 문장의 정량적 근거가 §4 의 구간별 비용 표입니다.

</details>

## Q6. (Analyze)

지연이 그대로인데 대역폭이 큰 이유를 설명하라. 그리고 여정의 어느 구간에서 성능 변동이 주로 발생하는가?

<details>
<summary>정답 / 해설</summary>

**대역폭이 큰 이유 — 여정이 겹치기 때문입니다.**

```
채널 0  :  ACT ──tRCD── RD ──── 데이터
채널 1  :     ACT ──tRCD── RD ──── 데이터
채널 2  :        ACT ──tRCD── RD ──── 데이터
   ...      (32개 채널이 동시에 진행)
```

채널 32개가 서로 독립이므로 32개의 여정이 동시에 진행되고, 각 채널 안에서도 PC 2개와 뱅크 32개가 대기 시간을 겹칩니다.

> **요청 하나의 지연은 수십 ns 그대로이고, 동시에 진행되는 요청의 개수가 대역폭을 만듭니다.**

**성능 변동이 발생하는 구간 — 단계 ⑤(core die) 안입니다.**

행 히트면 `RD` 만, 행 미스면 `ACT`+`tRCD` 가 추가되고, 행 충돌이면 `PRE`+`tRP` 까지 붙습니다([01장](../../01_dram_operation/)). 반면 ①~④는 **매번 같습니다.**

즉 **성능 변동의 대부분이 셀 접근 구간에서 나옵니다.**

</details>

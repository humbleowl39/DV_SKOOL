## 왜 검증 엔지니어가 HBM 구조를 알아야 하는가

"HBM 검증"이라는 말을 처음 들으면 대부분 DRAM 셀과 tRCD·tRP 같은 타이밍 파라미터를 떠올립니다. 그래서 JEDEC 타이밍 표를 펴 놓고 "이걸 다 외워야 하나" 생각하게 됩니다. 그런데 실제 HBM 검증 직무 기술서를 읽어보면 요구 역량이 전혀 다른 이야기를 합니다 — **SystemVerilog/UVM VIP와 Testbench 개발**, **신규 Protocol 또는 Custom IP에 대한 UVM Agent 설계**, **Code/Functional Coverage Closure**. DRAM 타이밍이 아니라 SoC 검증의 언어입니다.

이 간극은 HBM이 무엇인지 오해할 때 생깁니다. HBM은 DRAM die를 여러 장 쌓은 것이 전부가 아닙니다. 스택 맨 아래에는 **Base Die(Logic Die)** 가 있고, 이 die가 각 채널의 read/write를 관리하고 refresh 주기를 돌리며 precharge/activate 커맨드를 발행합니다. 그리고 HBM4 세대부터 이 base die는 DRAM 공정을 떠나 **로직 공정**(Samsung 4nm, TSMC 3nm 급)으로 이동합니다. 로직 공정으로 가면 자리가 남고, 그 자리에 메모리 컨트롤러·전력 관리·ECC, 나아가 고객 전용 가속기까지 들어갑니다.

즉 검증 엔지니어가 마주하는 DUT는 DRAM 셀 어레이가 아니라 **base die 안의 digital IP와 mixed IP**입니다. 그래서 직무가 UVM·VIP·Coverage의 언어로 쓰여 있는 것입니다. 이 코스는 그 DUT가 어디에 있고 어떤 구조적 성질을 갖는지를 먼저 확정합니다. 그것을 모른 채 테스트벤치부터 짜면, 무엇을 scoreboard로 잡아야 하는지·어떤 축으로 coverage를 나눠야 하는지 판단할 근거가 없습니다.

## 이 코스의 위치 — 무엇을 다루고, 무엇을 다루지 않는가

DV SKOOL의 HBM 자료는 두 토픽으로 나뉩니다.

| 토픽 | 역할 | 다루는 것 |
|---|---|---|
| **`hbm` (이 코스)** | 검증 **대상**을 이해한다 | HBM의 구조·동작. 각 챕터 말미에 *"이 구조가 만드는 검증 문제"* 로 착지 |
| [`hbm_dv`](../hbm_dv/) (후속) | 검증 **실무**를 한다 | Custom Agent, VIP 전략, 환경 계층, V-Plan, Assertion, Coverage |

**문제 제기는 이 코스가, 해법은 [`hbm_dv`](../hbm_dv/)가** 담당합니다. 그래서 이 코스의 모든 챕터는 하드웨어 사실을 설명한 뒤 "그래서 검증에서 무엇이 깨질 수 있는가"까지만 가고 멈춥니다.

다루지 않는 것도 분명히 해 둡니다. 본 코스는 **검증 직무 범위**로 한정되어 있어, Wafer Bonding·Thinning·BEOL 같은 공정 상세, PDN 해석, Thermal/Stress 모델링은 다루지 않습니다. 그런 항목은 Bonding·Process Integration·DTCO 직무의 영역입니다. 다만 그 결과가 검증에 닿는 지점(예: base die가 로직 공정으로 이동한다는 사실)은 다룹니다.

## 학습 목표

코스를 마치면 다음을 할 수 있습니다:

- **Explain (이해)** HBM이 GDDR/DDR 대신 선택되는 이유를 대역폭·전력 관점의 인과로 설명
- **Identify (기억)** HBM 스택에서 검증 대상(DUT)이 되는 경계 — Core die / Base die / TSV / 인터포저 — 를 식별
- **Differentiate (분석)** 채널과 Pseudo-channel의 독립성 수준(semi-independent)을 구분하고 그것이 만드는 동시성 문제를 설명
- **Trace (분석)** HBM의 분리된 row/column 커맨드 인터페이스를 따라 하나의 read 트랜잭션 흐름을 추적
- **Analyze (분석)** Base Die를 구성하는 IP를 in-house / 3rd party / mixed로 분류하고 각각의 검증 접근이 왜 달라지는지 분석
- **Evaluate (평가)** 세대별(HBM2~HBM4) 구조 변화가 검증 범위에 미치는 영향을 판단

## 사전 지식

- **DRAM 기본 원리** — 셀 어레이, bank/bank group, activate·precharge·refresh의 의미. [DRAM / DDR 코스](../dram_ddr/) 참고
- **JEDEC 스펙 읽기** (선택) — 타이밍 파라미터와 Mode Register의 개념. [DRAM JEDEC Deep-Dive](../dram_jedec_dv/) 참고
- **검증 기초** (선택) — 본 코스는 검증 문제를 *제기*만 하므로 필수는 아니지만, [UVM 코스](../uvm/)를 알면 각 챕터의 🔍 절이 훨씬 구체적으로 읽힙니다

DRAM 기초가 없다면 [DRAM / DDR 코스](../dram_ddr/)를 먼저 보시길 권합니다. 이 코스는 DRAM 일반론을 반복하지 않고 **HBM이 다른 지점만** 다룹니다.

## 직무 기술서(JD)와의 매핑

이 코스는 **HBM Digital Design (검증)** 직무를 기준으로 설계되었습니다. 각 챕터가 어느 요구사항의 배경 지식인지 표시합니다.

| JD 요구사항 | 배경이 되는 챕터 |
|---|---|
| HBM 내 In-house·3rd Party **Digital IP 및 Mixed 설계** 검증 | Ch03, **Ch06** |
| **UVM 기반 검증 환경** 구성 및 Test Case 개발 | Ch04, Ch05 (검증 축·감시 대상의 근거) |
| 신규 Protocol / **Custom IP UVM Agent** 설계·구현 | **Ch06** (표준 VIP가 없는 대상이 무엇인지) |
| Code/**Functional Coverage Closure** | Ch04 (채널 독립성 = coverage 축) |
| **HBM, DDR/LPDDR Memory 검증** (우대) | Ch01~Ch05 전반 |
| Full-Chip **Mixed-Level 검증** (우대) | **Ch06** (mixed IP의 위치) |

실무 수행 방법 자체는 후속 토픽 [HBM 검증 실무](../hbm_dv/)에서 다룹니다.

## 코스 운영 방식

각 챕터는 다음 순서로 구성됩니다:

1. **학습 목표** — 챕터 완료 후 할 수 있는 것 (Bloom's Taxonomy 동사)
2. **Why care?** — 정의가 아니라 상황에서 출발
3. **직관 → 작은 예 → 일반화 → 디테일** — 순진한 시도가 실패하는 과정을 거쳐 정의에 도달
4. **흔한 오해** — 자주 틀리는 지점
5. **🔍 이 구조가 만드는 검증 문제** — 이 코스의 척추. 하드웨어 사실이 검증에서 어떤 구멍이 되는가
6. **핵심 정리 + 퀴즈**

본문 중간에는 **접힌 정답**이 달린 자가 점검 질문이 있습니다. 펼치기 전에 먼저 답을 정해 보세요.

## 학습 팁

:::tip[효율적 학습]
- **DUT부터 확정하기**: Ch03을 읽을 때 "내가 검증할 코드는 이 그림에서 어디에 있나"를 손으로 표시해 보세요. 이후 모든 챕터가 그 지점을 향합니다
- **산술로 확인하기**: 대역폭 = 총 버스 폭 × per-pin 속도 ÷ 8. 이 식 하나로 세대별 수치가 맞는지 스스로 검산할 수 있습니다
- **채널 구조는 그려보기**: 16채널 × 64-bit → 32 pseudo-channel × 32-bit를 직접 그리면 coverage 축이 눈에 보입니다
- **🔍 절은 메모하기**: 각 챕터의 검증 문제를 모으면 그대로 V-Plan 초안의 씨앗이 됩니다
:::

:::caution[가장 흔한 오해]
**"HBM 검증 = DRAM 셀·타이밍 검증"이 아닙니다.** 검증 대상은 스택 맨 아래 **Base Die 안의 digital/mixed IP**이며, HBM4 세대부터 이 die는 로직 공정으로 이동해 사실상 작은 SoC가 됩니다. Ch03에서 이 경계를 확정하고, Ch06에서 그 안의 IP 지도를 그립니다.
:::

:::note[수치 인용에 대하여]
본 코스의 수치는 JEDEC 보도자료·벤더 기술 문서 등 **공개 자료**를 근거로 하며, 서로 다른 출처가 충돌하는 경우 대역폭 산술로 교차 검증한 값을 채택했습니다. 정밀한 타이밍·전기적 파라미터는 **항상 JEDEC 원문을 우선**하세요. 단일 벤더 발표 수치는 그 사실을 함께 표기하고, 계산으로 유도한 값은 **추론(산술)** 으로 표시합니다.
:::
